# Conv Learnings - 2026-09-27

## 1. Porting a subsystem means sweeping every dependent assertion, not just adding the new files
**Topics:** cc-workflow, docs-infra

**Context:** Flipping RESUME-STATE from deleted-at-r-start to kept-across-conv broke assertions scattered well beyond r-start Step 7.6 — a r-commit rationale comment, `conv-branch-guard.sh` + `resume-state-check.sh` header comments, r-start's stale-context check (which would now false-positive), and two legacy r-start sections. The "RESUME-STATE is deleted mid-conv" fact was load-bearing in ~5 places.

**Learning:** After changing a cross-file invariant, grep the whole skill/script tree for the *old* fact (not just the file you edited) and fix every assertion — comments included, since a wrong comment re-teaches the wrong model. A single behavioral flip has a wide blast radius across an interlocking skill set.

**Pattern:**
```bash
grep -rniE "<old-fact phrasing>" .claude/ CLAUDE.md docs/
# then reconcile each hit: fix / neutralize-legacy / confirm-still-true
```

## 2. The hopper's "earn a row" filter is the structural difference from capture-straight-to-board
**Topics:** cc-workflow

**Context:** peerloop's §Issue Surfacing mandated writing every spin-off straight into `CURRENT-TASKS.md` as a `### [CODE]` body — so capture == a durable board row, and the board grew to 67 bodies / 56 queued. fps interposes a friction-free `HOPPER.md` where most items are dealt with the same conv and never become rows.

**Learning:** Separating *capture* (immediate, no-ask, git-tracked) from *commitment* (must earn a row, ruled deliberately via `/r-hopper`) keeps the durable board small without losing spin-offs. The r-end Step 0.8 gate is what makes the discipline enforceable — a conv can't close over un-ruled captures.
