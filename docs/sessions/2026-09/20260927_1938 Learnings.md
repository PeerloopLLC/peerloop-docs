# Conv Learnings - 2026-09-27

## 1. The guard commit-message strip must be newline-aware
**Topics:** cc-workflow, guards

**Context:** The `-m` message strip in `guard-dangerous-bash.sh` used `sed` (line-oriented), so a multi-line v2 commit message documenting a guarded command (`git push --force`) was never stripped and tripped the "Force push" guard.

**Learning:** Strip inert command-argument bodies with a slurp-mode pass (`perl -0777`) so the match spans newlines; bound a double-quoted body with `"([^"\\]|\\.)*"` to tolerate escaped quotes and stop at the first unescaped close, preserving detection of a real danger chained after the argument.

**Pattern:**
`perl -0777` + `"([^"\\]|\\.)*"` for newline/escape-aware command-argument exclusion in a scanner.

## 2. The guard's value is narrow; its false-positive surface is broad
**Topics:** cc-workflow, guards

**Context:** Investigation of peerloop vs fps `settings.json`.

**Learning:** peerloop's `deny` list already blocks the bare force-push forms declaratively; `guard-dangerous-bash.sh`'s only additive coverage is the `git -C … push --force` form the deny-prefix can't see. fps has no such hook at all (so the false positive is structurally impossible there) and relies on default prompting. The hook buys narrow protection at the cost of scanning whole command strings — the root of both false positives.

## 3. An r-end finding self-dispositioned to "FYI" has no forcing function
**Topics:** cc-workflow

**Context:** The Conv-458 data-vs-command finding was surfaced at r-end, marked "FYI / accepted," and recorded nowhere trackable — it was effectively buried until re-raised by the user.

**Learning:** A surfaced issue needs a channel with a forcing function, not a note. The hopper provides it (git-persistent + the Step 0.8 close-gate); a RESUME-STATE carried-findings list did not (a re-carried note could be silently dropped). Hence: retire carried findings, route close-surfaced issues to the hopper, handle first next conv.

## 4. peerloop r-end lacks fps's currency sweep
**Topics:** cc-workflow

**Context:** Comparing r-end across the two projects.

**Learning:** fps r-end Step 1b mechanically lists every path the conv changed (`git diff "$H"` working-tree-vs-heartbeat + `ls-files --others`, explicitly not `..HEAD`) and re-reads each for claims the conv falsified. peerloop has no equivalent — a real gap (captured to the hopper this close).
