# Conv Learnings - 2026-09-25

## 1. `<a download>` on an endpoint that error-returns JSON silently saves `download.json`
**Topics:** astro, cloudflare, ui

**Context:** Client reported a `download.json` "File wasn't available on site" on staging session-attachment downloads.

**Learning:** A bare `download` attribute on an `<a>` whose href streams a file on success but returns `Response.json(...)` (no `Content-Disposition`) on error makes the browser SAVE the error body — named after the URL's last path segment (`download`) + the JSON content type = `download.json`. Any auth/missing-object/storage error becomes a confusing phantom file instead of a visible error.

**Pattern:** Intercept the click, `fetch`, check `res.ok`, toast on failure, blob-download on success; keep the native `download` as a no-JS fallback. Realized as the behavior-only `client:load` island `ResourceDownloadEnhancer.tsx` (renders null, delegated document listener) so an SSR `.astro` file gains client behavior without converting its markup to an island.

## 2. The download 200 is HTTP-cached — cache-bust when re-testing via the bridge
**Topics:** testing, cloudflare

**Context:** After deleting the R2 object, a plain re-fetch still returned the old 200.

**Learning:** `/api/resources/:id/download` sets `Cache-Control: private, max-age=3600`, so the browser serves a prior successful download from cache. When reproducing the missing-object failure through the Chrome bridge, use `fetch(url, {cache:'no-store'})` (or `cache:'reload'` to evict) — otherwise the stale 200 masks the 404.

## 3. Staging had no R2-seed parity with local
**Topics:** deployment, testing, cloudflare

**Context:** Local `db:setup:local:dev` seeds R2 (`db:seed:r2:local`); staging `db:setup:staging:dev` did not.

**Learning:** Both environments run the same `0001_seed_dev.sql`, which inserts `session_resources` rows with `r2_key`s but can't PUT blobs. Local closed that gap; staging never did, so every seeded resource 404'd on staging. Parity fix: a single env-aware seeder + `db:seed:r2:staging` wired into the staging setup chain. Remote seeding must be **gap-fill** (skip existing keys) so it never overwrites real UI-uploaded objects.
