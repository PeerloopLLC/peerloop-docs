# Conv Learnings - 2026-09-05

## 1. Truncating a Tailwind-v4 computed box-shadow hides the real layer
**Topics:** astro, testing

**Context:** Probing whether `shadow-brian-pill` rendered, I read `getComputedStyle(el).boxShadow.slice(0,70)` and saw only `rgba(0,0,0,0) 0px 0px…` — concluded (wrongly) the shadow was dead.

**Learning:** Tailwind v4 `box-shadow` is a 5-layer composite `var(--tw-inset-shadow), …, var(--tw-shadow)` — the first four are transparent `0 0 #0000` defaults and the REAL shadow is the **last** layer. Never truncate the string; check `.includes('rgba(<color>')` or read the full value. Also: `querySelector('.cls')` returns the first match, which may carry the class with a default `--tw-shadow` — filter to the element whose `--tw-shadow` holds the real value.

**Pattern:**
```js
[...document.querySelectorAll('.shadow-brian-pill')]
  .find(e => getComputedStyle(e).getPropertyValue('--tw-shadow').includes('rgba(16')) // then read full boxShadow
```

## 2. Tailwind v4 translate utilities land on the `translate` property, not `transform`
**Topics:** astro

**Context:** After `hover:-translate-y-[1px]`, `getComputedStyle(el).transform` read `none`, so the lift looked broken.

**Learning:** Tailwind v4 `translate-*` utilities set the standalone CSS `translate` property (`translate: <x> <y>`), NOT `transform`. Verify a hover-lift via `cs.translate` (e.g. `"0px -1px"`), not `cs.transform`/matrix `m42`.
