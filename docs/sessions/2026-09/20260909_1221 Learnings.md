# Conv Learnings - 2026-09-09

## 1. The `jfg-dev*` timecard allowlist held across the July-7 client-merge window
**Topics:** cc-workflow, dual-repo

**Context:** Billing four months (May 6 → Sept 8) of daily timecards spanning the `[MERGE-BRIAN-JULY7]` window, where the client's `brian-*` branch commits carry colliding `Conv NNN` numbers.

**Learning:** Every day's `candidateBranches` showed only `jfg-dev-*` code branches — the `rTimecardDay.codeBranchAllowPattern` (`^jfg-dev`) filtered client branches out at source, including through early-July. No client commit was ever billed. The allowlist mechanism (built Conv 396) worked exactly as designed across the whole range.

## 2. Being on a client-namespace branch is a silent billing hazard
**Topics:** dual-repo, cc-workflow

**Context:** The code repo was found sitting on `brian-sep-05` at session start.

**Learning:** Because the timecard allowlist only bills `jfg-dev*`, any work committed on a `brian-*` branch would be silently excluded from billing (and could collide with the client's own `Conv NNN` commits). The branches were content-identical so the switch was zero-risk, but the hazard is invisible until a timecard comes up short — worth catching at branch-switch time, which `/r-start`'s `[RSTART-DIFFGATE]` is meant to do.
