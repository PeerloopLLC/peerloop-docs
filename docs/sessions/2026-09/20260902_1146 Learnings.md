# Conv Learnings - 2026-09-02

## 1. `h-full` on a reused card is context-dependent — and can silently stretch
**Topics:** astro, tailwind, css, layout

**Context:** The cover-story `CourseCatalogCard`, reused as the `/course/[slug]` entity-header banner, rendered at inconsistent heights across tabs (190px most, 282px on Reviews).

**Learning:** `height:100%` (`h-full`) is a no-op in a `flex-col` vertical list (list items are content-height), but inside a flex column that is a *stretched* item of an outer `lg:flex-row` (the `panelSpan="full"` layout), it resolves against a column height that grows with sibling/tab content — so the banner stretched. A class that's inert in one host is a bug in another. Remove `h-full` when a grid/list card is reused as a standalone banner; keep `min-h-*` as the floor.

**Pattern:**
Verify layout-sensitive changes by measuring the real rendered height across states (Playwright `getBoundingClientRect`), not by eye — the fix was confirmed 190px-stable on every tab for visitor + enrolled.

## 2. Adding cross-file imports mid-session re-triggers the stale Vite deps brick
**Topics:** astro, cloudflare, deployment, dev-server

**Context:** After adding `CourseCatalogCard`/`formatPrice`/band imports across `[...tab]`/`book`/`success`, the running dev server 500'd on the stripe-importing route with `The file does not exist at ".../.vite/deps_ssr/stripe.js?v=<hash>"`.

**Learning:** This is the `[DEVSRV-STALE]`/`[VITE-DEPS-WATCH]` variant, not a code defect — new imports make Vite re-optimize deps and mint a new hash the long-running `astro dev` still holds stale. Tell: build is clean, only the running server 500s. Fix: `npx astro dev stop` → `rm -rf node_modules/.vite` → restart. Never port-kill (`lsof -ti` returns Chrome).

## 3. A JSX comment cannot sit between element attributes
**Topics:** astro, jsx

**Context:** Adding a `{/* … */}` rationale comment between `<CourseCatalogCard>` attributes produced 12 `astro check` ts errors (unterminated string / identifier expected).

**Learning:** `{/* */}` is only valid where a JSX *child* is valid, never between attributes. Put attribute rationale in a comment *above* the element (or in frontmatter).

## 4. `IconLabelChip` is hook-free → SSR-safe in `.astro`
**Topics:** astro, react

**Context:** Needed Level/students chips in an `.astro` page.

**Learning:** A presentational React component with no hooks renders to static HTML server-side in Astro with no `client:*` directive — confirmed by grepping the component for `useState/useEffect/useRef` before use.

## 5. CTA color audit — status coding is semantic, action buttons are not
**Topics:** design-system, ui, tailwind

**Context:** User flagged green + blue CTAs coexisting on `/course/[slug]/sessions`.

**Learning:** In this codebase green=completed/done and blue=booked/active is an *intentional, consistent* convention inside progress/stepper widgets (ModulesTab bar, CourseJourneyStepper steps, CourseProgressCard pills). But the primary action Buttons ignore it — "Book"/"Enroll"/"Join" flip between green `variant="course"` and blue `variant="primary"` with no rule (same Book action is green on success.astro, blue in SessionRoom). App-wide: 144 blue-primary vs 18 green-course Button variants; ~10 same-page mixing sites, all in the course/booking flow.
