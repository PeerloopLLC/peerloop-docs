# Conv Learnings - 2026-09-24

## 1. A masked exit code hid 10 real test failures ([TBK] recurrence)
**Topics:** testing, cc-workflow

**Context:** `npm run verify > log 2>&1; echo "EXIT=$?"` in a backgrounded command — the trailing `echo` succeeded, so the background task reported "exit code 0" while the log showed 2 failed files / 10 failed tests, and `build` never ran (`&&` short-circuit).

**Learning:** A trailing command after a piped/redirected `verify`/`test` masks the real exit; the background "exit code" is the *last* command's. Capture the real code INTO the log and always read the `Test Files … passed` line, never trust a bare "exit 0". The visual-confirmation step is what surfaced it — a green claim was standing on a masked failure.

**Pattern:**
```bash
npm run verify > log 2>&1; echo "REAL_VERIFY_EXIT=$?" >> log
grep REAL_VERIFY_EXIT log
```

## 2. Adding a query filter breaks every fixture that assumed the old filter
**Topics:** testing, d1

**Context:** Adding the active-teacher `EXISTS` gate to the catalog + rails queries broke catalog, discovery-rails, smart-feed, and PLATO scenario tests — all seeded courses without a `teacher_certifications` row.

**Learning:** A new inclusion predicate on a shared query has a blast radius across every test that seeds the gated entity. Grep for all fixtures that INSERT the entity and add the new precondition; add a regression test that asserts the *exclusion* (a teacherless course is hidden) so the gate can't silently regress.

## 3. Auto-cert makes an explicit self-cert a 409 — model the new invariant, don't fight it
**Topics:** testing, api

**Context:** PLATO scenarios did an explicit self-cert POST after course creation; auto-cert now certifies the creator at creation, so that POST returns 409 "already a Teacher".

**Learning:** When a behavior becomes automatic, downstream flows that did it manually become redundant/conflicting. The faithful fix is to convert the manual step into a *discover* (GET the auto-created state) rather than loosen the endpoint's 409 contract (which would affect all callers, incl. certifying real students).

## 4. `.dev.vars` can be silently emptied and only surfaces as a blanket 500
**Topics:** cc-workflow, cloudflare

**Context:** A 5-byte `.dev.vars` (mtime Sep 23) → `JWT_SECRET` missing → "Server configuration error" 500 on the Smart Feed and ~130 endpoints. Gitignored, so no git restore.

**Learning:** A blanket "Server configuration error" that fails in ~1ms is an env/config guard, not a logic bug — check `.dev.vars` key presence first (names only, never values). Recovery is user-supplied (their own copy / password manager), not git.
