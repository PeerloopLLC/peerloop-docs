# Conv Learnings - 2026-09-10

## 1. Port a skill by reading a real target artifact, not by assuming schema parity
**Topics:** cc-workflow, obsidian, skills

**Context:** The SPT `r-block-report` exists for Dataview column-parity with meeting/slack exports. Peerloop's coding timecards turned out to use a different inline-field schema entirely.

**Learning:** Before porting a vault-parsing skill, open an actual target note. Peerloop coding cards carry `Focus/Start/End/Adjust/Billable/Bill?/Convs/Blocks` — **no** `Channel/Who/Via/Slack` — and the source-folder config key is `rTimecardDay.vaultPath`, not SPT's `outputDir`. Blindly copying SPT's `DEFAULT_COLUMNS` and `loadConfig` would have produced empty columns and an unresolved source dir.

---

## 2. Peerloop's `Billable` field is authoritative; the naive End−Start+Adjust is not
**Topics:** obsidian, billing

**Context:** SPT computes `Hours` from `Start`/`End`/`Adjust`. Peerloop's timecard-day script already emits a slot-rounded, overflow-capped `Billable` (e.g. `7h10`).

**Learning:** For a Peerloop billing report, parse `Billable` for `Hours` (fallback to the computed value only when absent). Aug 10, 2026: `Billable 7h10` → 7.17h, whereas End−Start+Adjust gives 7.13h — the difference is Peerloop's slot rounding, which is the number actually billed.
