# Conv Learnings - 2026-09-27

## 1. peerloop r-end had no self-falsification check; the 3 dispatch agents only build forward
**Topics:** cc-workflow, docs-infra

**Context:** Ruling the Conv-459 hopper item (port fps Step 1b currency-sweep to peerloop r-end).

**Learning:** peerloop's r-end DISPATCH agents (learn-decide, update-plan, docs) build the Extract/PLAN/docs *forward* from the conv; none re-reads the conv's own changed files *backward* asking "did this edit make an existing claim untrue?". Confirmed by grep — no `currency`/`falsif`/`re-read`/`stale` language existed in r-end beyond the editorial-vendor-doc note — so the gap the hopper item flagged was real.

## 2. The heartbeat asymmetry between the two repos drives how the currency sweep is anchored
**Topics:** cc-workflow, dual-repo

**Learning:** Only `peerloop-docs` carries the `Conv NNN start — MACHINE` heartbeat commit; the code repo (`Peerloop`) has none. So a working-tree-vs-heartbeat diff (`git diff "$H"` + `ls-files --others`) works directly for docs, but the code repo must be anchored by the docs heartbeat's *timestamp* (`git log --since=<ts>` + `diff --name-only HEAD` + untracked). This mirrors how fps anchors its non-heartbeat PKM repos.
