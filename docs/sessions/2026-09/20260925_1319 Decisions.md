# Conv Decisions - 2026-09-25

## 1. Fix scope for the download bug — C (harden now + staging data follow-up)
**Type:** Strategic
**Topics:** astro, cloudflare, ui

**Trigger:** The `download.json` symptom had two independent causes: missing R2 objects (data) and a bare `download` attr that masks any error (implementation).

**Options Considered:**
1. A — harden the implementation only
2. B — fix the staging data only
3. C — both: A now, B as a scoped follow-up ← Chosen

**Decision:** Do the durable client-side hardening immediately, then fix the staging seed data.

**Rationale:** The two are independent; the hardening protects against any future missing-object case regardless of environment, and the data fix restores the demo downloads on staging.

**Consequences:** `ResourceDownloadEnhancer` island shipped (A); staging R2 seed step added (B).

## 2. Seed real, obviously-DEMO sample files (shared local + staging), not blank placeholders
**Type:** Implementation
**Topics:** testing, deployment, cloudflare

**Trigger:** Choosing what bytes to seed into R2; staging is client-visible.

**Options Considered:**
1. Keep tiny blank placeholders (local's prior behaviour)
2. Real, valid sample files with "DEMO" shown prominently, used for BOTH local and staging ← Chosen

**Decision:** Generate valid PDF/XLSX/DOCX/ZIP with "DEMO" + the resource name prominently, deterministically, and use them for local and staging.

**Rationale:** On staging the client could actually open a downloaded file; a blank file is confusing, and clearly-marked DEMO content makes it obvious the data is sample content, not production.

**Consequences:** New `scripts/demo-assets.mjs` (pure-JS generator + store-only ZIP writer); `seed-r2-dev.mjs` PUTs demo files; local reseeded; staging seeded 7/7 (byte-identical to local).

## 3. Staging R2 seeder is gap-fill (never overwrites)
**Type:** Implementation
**Topics:** deployment, cloudflare

**Trigger:** A blind seeder would overwrite real UI-uploaded staging files with placeholders.

**Options Considered:**
1. Overwrite all keys (local behaviour)
2. Gap-fill on remote — skip any key whose object already exists ← Chosen for remote

**Decision:** Local overwrites (idempotent); remote/staging skips existing objects.

**Rationale:** Protects any real uploaded content on staging; the seeder only fills genuinely-missing demo objects.

**Consequences:** `--remote` implies gap-fill in `seed-r2-dev.mjs`; existence-probed per key before PUT.
