# Conv Learnings - 2026-09-01

## 1. Measure glyph baselines, not element box-tops, for text alignment
**Topics:** astro, testing

**Context:** A 3px meta-line misalignment; I added `leading-[20px]` and reported it "verified −0.9px" — but that compared `getBoundingClientRect().top` of a 12px line-box vs a 20px line-box (not comparable). The user caught it was a visual no-op.

**Learning:** When line-heights differ between the elements being compared, box `.top`/`.height` are misleading. Measure the actual glyph ink with `Range.getBoundingClientRect()` (select the text node) and compare baselines/bottoms. The `leading` change was a no-op because centring 12px glyphs in a 20px box leaves them where they were.

**Pattern:**
```js
const r = document.createRange();
r.selectNodeContents(textNode);
r.getBoundingClientRect().bottom; // comparable baseline across differing line-heights
```

## 2. An inline `<a>` around an inline-flex chip inflates to a ~26px line box
**Topics:** astro

**Context:** Creator/rating chips (inline-flex, 20px icon) wrapped in inline `<a>` links floated ~3px above a plain sibling text span in an `items-center` flex row.

**Learning:** An inline anchor wrapping an inline-flex element is laid out in a line box whose leading makes the anchor taller than the chip (26.3px vs 20px), and the chip baseline-aligns high within it. Fix: put `inline-flex items-center` on the wrapper so it collapses to the child's own height.

## 3. A component's base `relative` class beats an appended `absolute`
**Topics:** astro

**Context:** `CommunityAvatar` renders `className="relative ... ${className}"`; passing `absolute ...` from the host didn't make it absolute — it stayed `position: relative` (in-flow), inflating the band.

**Learning:** Tailwind orders `.relative` *after* `.absolute` in the generated stylesheet, so class-attribute order doesn't decide the winner — the later CSS rule does, and `.relative` wins. To force absolute, wrap the component in an absolutely-positioned element (don't fight the cascade with a class).

## 4. The `lh` CSS unit works for reserving N text lines
**Topics:** astro

**Context:** Wanted the title to always reserve exactly 2 (mobile) / 3 (desktop) lines of height.

**Learning:** `min-h-[2lh]` / `min-h-[3lh]` resolve to 2×/3× the element's computed line-height and are self-adjusting; verified supported in the target Chrome. Cleaner than hard-coding px.

## 5. Dev-CSS staleness on newly-referenced arbitrary classes (reconfirmed)
**Topics:** astro, cc-workflow

**Context:** Every new arbitrary class this conv (`-top-[23px]`, `size-[46px]`, `min-h-[3lh]`, `w-[180px]`, `@xl:w-[156px]`, `pl-[100px]`, `@xl:ml-auto`) computed to 0 / stale on the ClientRouter View-Transition swap path until the dev server was restarted.

**Learning:** Confirms the existing memory: after adding an arbitrary Tailwind class mid-session, restart the dev server + clear `node_modules/.vite`, and verify on a real in-app tab *swap* (not a full `navigate()`), which masks the bug. Standard (non-arbitrary) classes like `inline-flex`/`items-center` need no restart.
