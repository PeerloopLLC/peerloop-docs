# Conv Learnings - 2026-09-21

## 1. A client-authored branch that is a linear superset is safe to curate by cherry-pick
**Topics:** dual-repo, cc-workflow, git

**Context:** Code repo is shared with the client (Brian); he pushed 14 commits on `brian-sep-05` on top of our `jfg-dev-15`.

**Learning:** When a branch is a strict linear superset (0 divergence, verified via `git rev-list --left-right --count A...B`), cherry-picking a contiguous prefix onto a fresh branch is conflict-free by construction, and cherry-picking in the commits' ORIGINAL order automatically satisfies all inter-commit dependencies. The "ignore" set being exactly the tip made pruning trivial.

**Pattern:**
```
git rev-list --left-right --count jfg-dev-15...origin/brian-sep-05   # confirm one side is 0
git cherry-pick -x <sha>   # in original order; preserves client authorship + records source SHA
```

## 2. Preserve deleted-but-wanted functionality as a dormant compiling component, not a comment blob
**Topics:** cc-workflow, astro, code-quality

**Context:** Brian's FILTER-STRIP removed the Level/Length/Available-soon filters the user had deliberately kept; user wanted them preserved "as components that are commented out."

**Learning:** A never-imported, self-contained component compiles under tsc + passes eslint (eslint doesn't flag unused FILES — that's knip's job, and knip isn't wired into codecheck here), so it's gate-clean today. But a faithful preservation must capture BOTH halves — the control component AND the consumer-side logic (FilterState fields + fetch + filter branches) — or "uncomment to restore" won't actually work.

**Pattern:** Extract → new dormant component w/ re-enable checklist header; comment the import+mount at the call site; preserve the consumer logic as a commented block; add a guard comment to any backend endpoint it depends on so a dead-code sweep won't delete it.

## 3. "Mobile broken" on a fresh dev server is usually dev-CSS/cache staleness, not code
**Topics:** astro, testing, cc-workflow

**Context:** User reported lost mobile responsiveness across pages; a hard refresh fixed it.

**Learning:** Newly-added classes + client islands can serve stale on the dev server's View-Transition/cache path until a hard reload. The discriminator: does a HARD reload fix it (→ cache) vs. only-after-in-app-nav (→ still cache/stale CSS)? A 375px iframe-harness DOM measurement (0 overflow / 0 offenders) is the authoritative confirmation there's no real regression.

## 4. Chrome bridge "extension not connected" — first check the extension sign-in
**Topics:** cc-workflow, obsidian

**Context:** Bridge repeatedly reported "extension is not connected" on M4Pro; `/chrome` didn't fix it.

**Learning:** `/chrome` enables the feature on the CC side only — it does not establish the extension handshake. The #1 actual cause this time was simply not being signed into the Claude extension in Chrome. Captured as `[BRIDGE-CONNECT]` (`reference_chrome_bridge_connection_recovery.md`).
