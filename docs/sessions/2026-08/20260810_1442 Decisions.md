# Conv Decisions - 2026-08-10

## 1. Adopt the client's pill elevation as tokens, keep it local
**Type:** Implementation
**Topics:** merge-brian, tokens

**Trigger:** Client asked for hover-lift + shadow on the `/courses` topic pills.

**Options Considered:**
1. Inline his rgba values
2. Adopt verbatim as named `brian-*` tokens ← Chosen
3. Decline again

**Decision:** Adopt his exact two-layer shadow and 1px lift, carried as `--brian-pill-shadow{,-hover}`; hover no longer tints. Scope kept deliberately LOCAL to that row (user decision) — other pill surfaces stay flat.

**Rationale:** The ledger's objection was the eight raw `rgba` stacks, not the effect. His tint turned out to be `--brian-ink`, already adopted, so the whole thing cost no new colour.

**Consequences:** `NOT-ADOPTED.md` amended; a component docstring now records why the treatment must not be propagated on consistency grounds (the Conv-433 `[COMM-IDENT]` reversal).

## 2. Adopt the per-card CTA by sharing the detail page's resolver
**Type:** Strategic
**Topics:** architecture, course-cta, merge-brian

**Trigger:** Client asked for a four-state CTA on every course card — previously declined.

**Options Considered:**
1. Implement his four states literally (reproduces the divergence)
2. Call the detail page's own resolver from a shared lib ← Chosen
3. Decline again

**Decision:** Move `buildCoursePrimaryCta` to `@lib/course-cta`; add `nextSessionId` to the client snapshot aligned to `computeCourseJourney`'s predicate; every surface resolves through one set of branches. Keep a fifth state (booked session) his spec omits.

**Rationale:** The review declined his CTA because it disagreed with the detail page. Sharing the function removes the possibility rather than the symptom.

**Consequences:** Three surfaces provably agree (verified live on the exact student who would have shown the bug). A parity test now fails if a second implementation reappears.

## 3. Suppress the enrol CTA for creators only
**Type:** Implementation
**Topics:** course-cta, roles

**Trigger:** A community moderator saw blank cards on courses they never purchased.

**Options Considered:**
1. Special-case moderators
2. Unpick the union — suppress for creators only ← Chosen

**Decision:** `myCourseIds` (enrolments + teaching certs + created + moderated, all suppressed alike) reduced to created courses only; teachers routed to their teaching workspace; cancelled enrolments read as not-enrolled on both surfaces.

**Rationale:** Four unrelated relationships were being treated as one. Only authorship genuinely has no next step to offer.

**Consequences:** Also fixed a case neither ticket named — a certified teacher who never enrolled previously got no CTA at all.

## 4. Route the teaching request to the creator, and widen who may recommend
**Type:** Strategic
**Topics:** flywheel, authorization, certificates

**Trigger:** Building the student's request-to-teach flow.

**Options Considered:**
1. Message the assigned teacher (who could already act)
2. Message the creator and widen `recommend.ts` to accept them ← Chosen
3. Message the creator without widening (arrives at someone who cannot act)

**Decision:** The request goes to the course creator; `recommend.ts` now accepts creator-of-this-course as well as certified-teacher-of-this-course.

**Rationale:** User's call, and it matches CLAUDE.md's product model (creators certify teachers) — which the built endpoint contradicted. Creators are not reliably certified for their own courses (seed: Guy 4/4, Gabriel 0/2), so without the widening half the courses would dead-end.

**Consequences:** A documented model/code contradiction resolved in favour of the docs. Negative test added so the widening cannot drift into "any authenticated user".

## 5. Give creators their own request queue rather than widening the teaching workspace
**Type:** Strategic
**Topics:** architecture, roles

**Trigger:** Discovering the API widening had no reachable UI.

**Options Considered:**
1. Widen `/teaching/courses/[id]` guards
2. New creator-facing request queue ← Chosen
3. Both

**Decision:** New **Requests** tab in `/creating` + `GET /api/me/teaching-requests`, scoped by authorship. Notification `actionUrl` repointed there.

**Rationale:** The teaching workspace's student list is scoped `WHERE assigned_teacher_id = <viewer>`, so widening the guard alone would have rendered an EMPTY list — worse than the redirect, because it reads as the request having vanished. The creator studio had no per-student list at all.

**Consequences:** Also fixes the notification landing on the wrong tab. Verified on both an uncertified creator (reaches it) and a certified one (acts on it).

## 6. Build a gate for invented token/icon names
**Type:** Implementation
**Topics:** tooling, testing

**Trigger:** Three invented names shipped in one component and passed every gate.

**Options Considered:**
1. Be more careful
2. Static gate over project-owned families ← Chosen
3. Validate every utility (needs Tailwind's full built-in surface; noisy)

**Decision:** `scripts/check-token-names.ts`, wired into `verify` and `/w-codecheck` as check #10. Polices only families this repo declares and Tailwind does not ship.

**Rationale:** "Be more careful" is not a mechanism. Restricting to owned families makes "declared or invalid" exact and keeps false positives at zero — which is what keeps a gate switched on.

**Consequences:** Found 6 pre-existing `text-warning-600/700` defects immediately.
