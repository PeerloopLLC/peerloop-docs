# Conv Learnings - 2026-08-23

## 1. A display convention was silently load-bearing in tooling
**Topics:** cc-workflow, task-board

**Context:** The user asked to strip the ordinals from `## 🎯 Now` in `CURRENT-TASKS.md` because position already encodes order. But `current-tasks-check.sh:40` parsed Now-TOC lines with `/^[0-9]+\. \[/` — the numeric prefix was a hard dependency of the consistency checker, not just decoration. Stripping the numbers would have made every task read as an ORPHAN.

**Learning:** Before removing a "cosmetic" markup convention, grep the tooling that parses the file. A purely-visual-looking prefix (an ordinal, a bullet style) can be the parser's anchor; removing it silently converts every entry into an orphan/dangling result.

**Pattern:**
Make the parser **tolerant of both** old and new forms instead of doing a flag-day switch — legacy/cross-machine files and existing test fixtures keep validating through the transition.

```awk
# Now-line match accepts both new bullet and legacy ordinal forms
(/^- \[/ || /^[0-9]+\. \[/)
```

## 2. Max ordinal ≠ line count when ties and skips exist
**Topics:** task-board

**Context:** The list's highest number read `46`, so it looked like 46 items, but the checker counted 48 Now codes after the migration to bullets.

**Learning:** Repeated ordinals (four `2.`s) add lines beyond the max value, and a skipped number (`40`) subtracts one — here they happened to net to 48. When a count "looks off," reconcile the arithmetic (max value ± duplicates ± skips) before assuming content was dropped.
