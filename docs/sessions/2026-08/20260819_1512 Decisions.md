# Conv Decisions - 2026-08-19

## 1. Sidebar long-menu: pin header + account, scroll the middle (not chevrons, not whole-rail scroll)
**Type:** Implementation
**Topics:** ui-css, ux

**Trigger:** User asked whether a long nav should scroll or use up/down chevrons like the stepper.

**Options Considered:**
1. Up/down chevron paging (like the horizontal stepper)
2. Scroll the whole rail (status quo) with a thin/auto-hiding bar
3. Pin header + account row, scroll only the middle nav region ← Chosen

**Decision:** Idiomatic long-menu treatment — pin the brand header and the account row, scroll the primary-nav region between them, thin auto-hiding scrollbar + background scroll-shadow.

**Rationale:** Chevrons are non-idiomatic and worse for a *vertical* nav (native wheel/trackpad is the expected gesture); pinning the account + brand matches Slack/Discord/Linear/Notion. Only the small account row pins (not the whole utility cluster) so the scroll region keeps usable height on short viewports.

**Consequences:** Restructured both rail variants + the drawer; **retired the Conv-368 SIDEBAR-COLLIDE merge observer** (superseded — a real scroll region means the clusters can't collide); kept the `@media(max-height:500px)` compaction.

## 2. Scroll-shadow via background (Lea Verou), not a content mask
**Type:** Implementation
**Topics:** ui-css, ux

**Trigger:** The content-mask version was invisible in the gaps between tall buttons.

**Options Considered:**
1. `mask-image` fading the nav content at the edges (JS-toggled)
2. Pure-CSS background scroll-shadow (`background-attachment: local`) ← Chosen

**Decision:** Paint the shadow on the scroll region's background; remove the JS scroll listener entirely.

**Rationale:** Background shadow shows continuously (including gaps), auto-hides at each end with no JS, and is VT-persist-safe (pure CSS).

**Consequences:** Removed the `[SBAR-FADE]` listener + `data-fade` attributes; intensity dialed to `rgba(15,23,42,0.154)/24px`.

## 3. Tab bar horizontal scroll: conventional only (no plain-wheel hijack)
**Type:** Implementation
**Topics:** ui-css, ux

**Trigger:** User asked to mirror the sidebar wheel-capture for the tab bar and whether Shift+Scroll is the convention.

**Options Considered:**
1. Translate plain vertical wheel → horizontal (mirror the sidebar), chain at ends
2. Conventional only — native trackpad-horizontal + Shift+Wheel + the arrow buttons ← Chosen (by user)

**Decision:** No code change. Rely on the native `overflow-x-auto` behaviour (Shift+Wheel, trackpad swipe) plus the existing scroll arrows.

**Rationale:** A plain-wheel→horizontal hijack surprises trackpad users (a vertical swipe over the thin strip would nudge the tabs). The conventional path already works; user confirmed.

**Consequences:** None (tab bar unchanged).

## 4. Course stepper container breakpoint 768px → 600px
**Type:** Implementation
**Topics:** astro, ui-css

**Trigger:** Full stepper never appeared at desktop.

**Options Considered:**
1. Keep 768px (unreachable)
2. Lower to ~600px ← Chosen

**Decision:** Set the dropdown↔full breakpoint to 600px.

**Rationale:** Desktop content column is a fixed 648px; full stepper min-width is 550px, so 600px shows the full stepper at desktop with margin and still drops to the dropdown on mobile.

**Consequences:** `@[768px]:` → `@[600px]:` in `CourseJourneyStepper.astro` (both sections).
