# Conv Learnings - 2026-08-10

## 1. For layout work the gates are not evidence
**Topics:** testing, astro, cc-workflow

**Context:** Phase A's first cut made `AppLayout`'s content row `lg:flex-row` whenever a right panel was present. `tsc --noEmit`, `astro check` (0 errors / 0 warnings), ESLint, `npm run build` and 6383 tests all passed — on a course page whose content column had collapsed to zero width and rendered nothing.

**Learning:** A green gate set says the code compiles and the assertions that exist still hold. It says nothing about whether a page lays out. Any change to a flex/grid container needs a measurement, and the measurement has to be of boxes, not of screenshots or of markup presence — the markup was present and correct throughout.

**Pattern:** After a layout change, measure `getBoundingClientRect()` for every child of the changed container and assert the invariants directly: content width non-zero, siblings strictly left-to-right without overlap, and the panel absent below its breakpoint.

## 2. A slot that stacks and a slot that columns are different structures
**Topics:** astro, docs-infra

**Context:** `AppLayout`'s `sub-nav` slot holds either a 196px vertical rail (opt-in `'left'` layout) or a full-width horizontal strip (the `'top'` default). Adding a right panel as a third child of the same flex row treats both identically, which is wrong for the strip.

**Learning:** The right panel pairs with the **content**, not with the row. Two nested rows express both layouts with one structure: the outer row's direction keys on the sub-nav's orientation alone, and content+panel share an inner row.

**Pattern:** When the wrapper must vanish for the common case, give it `display: contents` rather than branching the markup — the children stay flex items of the grandparent, the parent's `gap` still applies across it (verified: `/profile` content sits at x = 364 + 196 + **16**), and no duplicate `<slot />` is needed.

## 3. Verify list ordering before reading a truncated list as evidence
**Topics:** cloudflare, deployment, cc-workflow

**Context:** `wrangler deployments list --name peerloop-cron-staging | head -14` showed 2026-04-21 entries. Read as "newest first", that means staging's cron is four months stale and missing every job built since — a serious, wrong conclusion that was one sentence away from being reported.

**Learning:** `wrangler deployments list` prints **oldest-first**. A truncated head of an unknown-ordered list is not evidence of anything. Count the entries and read the tail before concluding.

**Pattern:** `... | grep -c "^Created:"` then `| tail -3` — establishes both the ordering and the true newest in one pass.

## 4. Schema edits do not reach an already-migrated remote D1 — and nothing detects it
**Topics:** d1, deployment

**Context:** Conv 434 added `enrollments.teaching_request_sent_at` to `0001_schema.sql` and shipped no staging deploy. Staging sat two convs behind with the column missing; the CTA resolver and course pages query it.

**Learning:** `[D1-SCHEMA-REMOTE]` is documented, but nothing *detects* the drift — it was found only because this conv happened to look. A name-level schema signature diff is about six lines and catches it deterministically.

**Pattern:** `SELECT m.name || '.' || p.name FROM sqlite_master m JOIN pragma_table_info(m.name) p WHERE m.type='table' ...` on both sides, sorted, then `diff`. Compare NAMES, not counts — a rename leaves counts equal.

## 5. Order the schema change before the code that needs it
**Topics:** d1, deployment

**Context:** Deploying Conv 434/435 code against staging's older DB would have thrown `no such column` on `/courses` and `/course/{slug}` for the whole window.

**Learning:** ALTER first, deploy second. An additive nullable column is inert until code references it, so the intermediate state is harmless; the reverse ordering has a guaranteed broken window on exactly the pages being demoed.
