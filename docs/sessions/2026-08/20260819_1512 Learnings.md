# Conv Learnings - 2026-08-19

## 1. Container-query breakpoint must match the ACTUAL capped content width, not a viewport guess
**Topics:** astro, ui-css, tailwind

**Context:** The course stepper dropped to its dropdown form at every desktop width.

**Learning:** The content column is `max-w-[1248px]`-capped and shares its row with a fixed 284px right panel, so at any desktop viewport it tops out at a **fixed ~648px**. A container-query breakpoint of 768px is therefore *unreachable* at desktop. When choosing a container breakpoint, measure the real container's maximum width (here via the Chrome bridge) rather than reasoning from viewport sizes — a max-width-capped, panel-sharing column does not grow with the viewport.

**Pattern:**
Measure `element.getBoundingClientRect().width` of the actual `@container` element at the widest realistic viewport; set the breakpoint below that AND above the component's measured minimum content width (stepper min = 550px → breakpoint 600px).

## 2. Verify Tailwind-v4 arbitrary-variant behaviour against the BUILT CSS, not intuition
**Topics:** tailwind, astro, debugging

**Context:** The `@[768px]:` arbitrary container-query syntax was initially blamed as invalid v4 — a "fix" was about to be applied.

**Learning:** `@[768px]:hidden` / `@[768px]:block` ARE valid in Tailwind v4.3.3 (they compile to `@container (width>=768px){ .\@\[768px\]\:… }`), and the cascade order was correct. Grepping the built `global.*.css` for the generated rule + `container-type:inline-size` disproved the syntax theory in one step and redirected to the real cause (container width). Probe the authoritative artifact (built CSS) before rewriting on a training-data hunch.

## 3. Styling a scrollbar makes it layout-taking → guard the cross axis
**Topics:** ui-css, cross-browser

**Context:** A horizontal scrollbar appeared in the sidebar whenever the vertical one did.

**Learning:** Setting `scrollbar-width: thin` / `scrollbar-color` (or `::-webkit-scrollbar`) makes Chrome render a **classic, layout-consuming** bar (~11px on macOS) instead of the zero-width overlay. That eats content width, and because `overflow-y:auto` forces the computed `overflow-x` to `auto`, the `w-full` children overflow by the bar width → a spurious horizontal scrollbar. Fix: pair vertical `overflow-y-auto` with explicit `overflow-x-hidden` on any styled-scrollbar scroll region.

## 4. Fade the BACKGROUND, not the content, for a "more items" cue on a tall-row list
**Topics:** ui-css, ux

**Context:** A CSS `mask-image` scroll-shadow only showed where a label sat near the edge; the tall buttons' inter-row gaps stayed blank.

**Learning:** Masking the *content* only dissolves pixels that exist at the edge, so with tall, sparsely-filled rows the cue disappears in the gaps. A **background** scroll-shadow (Lea Verou's `background-attachment: local` cover gradients over `scroll`-attachment shadow gradients) paints behind the transparent rows and shows *continuously*, including in the gaps — and auto-hides at each end with **no JS** (the local-attachment cover scrolls with content and masks the shadow exactly at the top/bottom limit).

**Pattern:**
4 stacked backgrounds — `linear-gradient(bg → transparent) top/bottom` (attachment: local) + `radial-gradient(dark → transparent) top/bottom` (attachment: scroll); `background-size: 100% 44px, 44px, 18–24px, 18–24px`.

## 5. Wheel scroll-chaining: capture at the container + `overscroll-behavior: contain`
**Topics:** ui-css, dom-events

**Context:** Wheeling over the sidebar mostly scrolled the main content panel instead of the nav.

**Learning:** A pinned-header/scroll-middle/pinned-footer layout leaks the wheel to the page in two ways: (a) the pointer is over a *non-scrolling* pinned region, and (b) the inner scroll region hits its boundary and chains out. `overscroll-behavior: contain` fixes only (b) for the native-target case. To fully "capture wheel anywhere over the aside", add a `wheel` listener on the container (`passive:false`) that forwards `deltaY` to the inner scroll region and `preventDefault`s — no-op when the region can't scroll (so the page still scrolls when the nav fits), normalize `deltaMode` (Firefox line-based / page), and skip `ctrlKey` (pinch-zoom).

## 6. `check:tokens` is the ONLY gate that catches invented design tokens
**Topics:** tailwind, testing, tooling

**Context:** `text-text-secondary` (no such token) passed tsc, ESLint, and astro-check but rendered the "Steps" label with no colour.

**Learning:** An invented Tailwind color/type token is silent to every type/lint/astro gate — it just emits no CSS. Only `npm run check:tokens` (the invented-name catalogue check) sees it. Run `check:tokens` after adding any `text-*`/`bg-*`/`border-*` utility with a token name you're not 100% sure exists. Valid text tokens here are `text-{default,tertiary,primary}` — there is no `secondary`.
