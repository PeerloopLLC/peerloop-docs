# Conv Learnings - 2026-08-24

## 1. `| tail -N` on a verify/test command masks the real exit code
**Topics:** testing, cc-workflow

**Context:** Ran `npm run verify 2>&1 | tail -50` in the background; the task summary reported "exit code 0" and the tail ended with `[exited with code 0]` — but that was **tail's** exit, not verify's. Verify had 5 test failures. Nearly committed onto a red baseline.

**Learning:** Never pipe a gate command (verify/test/build) through `tail`/`head`/`grep` when you need its pass/fail — the pipe's last stage owns `$?`. Redirect to a file and capture the real code, or use `PIPESTATUS[0]`.

**Pattern:**
```bash
cmd > log 2>&1; echo "EXIT: $?"   # or: cmd | tail -50; echo "${PIPESTATUS[0]}"
```

## 2. Two concurrent `npm test` runs corrupt each other via the shared test DB
**Topics:** testing

**Context:** A broken-path full-suite run and a corrected one overlapped; the live log showed spurious `should query all courses/users` failures that don't reproduce solo.

**Learning:** The test suite uses a shared better-sqlite3 DB; two full suites at once contend and produce phantom failures. Run one at a time. If failures look like basic DB-count/seed assertions failing inexplicably, suspect concurrency before code.

## 3. Adding to the SQL dev seed breaks exact-count integration tests
**Topics:** testing, dual-repo

**Context:** `tests/integration/database.test.ts` asserts `TEST_DATA_COUNTS.users + 2` and `TEST_DATA_COUNTS.courses`. `TEST_DATA_COUNTS` is derived from `mockData` (users 9, courses 6), and the DB test reconciles the SQL-seed-only rows with hardcoded offsets. Adding Jack (+1 user, +1 course) to `migrations-dev` — but not `mockData` — broke both.

**Learning:** The SQL dev seed and `mockData` are parallel fixtures kept in loose sync by magic offsets in `database.test.ts` (the `+2` comment even itemizes "core admin + Fraser Gorrie"). Any user/course added to `migrations-dev/0001_seed_dev.sql` must bump those offsets. Run the FULL suite (not just unit) after a seed change.

## 4. `transition:persist` islands freeze server-rendered props after View-Transition nav
**Topics:** astro, ui-ux

**Context:** The Sidebar's active highlight never followed client-side navigation because the persisted island kept its first-render `currentPath` prop (`Astro.url.pathname`).

**Learning:** A `client:load` + `transition:persist` island is NOT re-rendered with fresh Astro props on a View-Transition swap. Any prop derived from `Astro.url` goes stale. Fix: hold it in island state and refresh on the `astro:page-load` event (the in-repo precedent is `AdminNavbar.tsx:108-120`).

**Pattern:**
```ts
const [pathname, setPathname] = useState(currentPath);
useEffect(() => {
  const s = () => setPathname(p => { const n = location.pathname; return p === n ? p : n; });
  s();
  document.addEventListener('astro:page-load', s);
  return () => document.removeEventListener('astro:page-load', s);
}, []);
```

## 5. Render a desktop layout in a sub-`lg` window via a same-origin iframe harness
**Topics:** cc-workflow, testing

**Context:** The Chrome window's CSS viewport was 1013–1231px but often below the 1024 `lg` breakpoint (and short at 674px), so screenshots kept rendering the mobile layout — the desktop sidebar is `hidden lg:flex`.

**Learning:** Inject a same-origin iframe at a fixed ≥1024 width (`width/min-width !important`, `transform: scale()` to fit) — media queries key off the iframe, so the desktop rail renders regardless of the outer window. Cookies carry, so the logged-in session persists. (Reference: `memory/reference_responsive_iframe_harness.md`, `[VPHARNESS]`.)

## 6. Enumerate the FULL failure list before characterizing test failures
**Topics:** testing, cc-workflow

**Context:** Confidently told the user "all 5 failures are pre-existing/unrelated" based on the tail-masked output that only showed one file. The clean run proved 2 of the 5 were caused by the seed change made this conv.

**Learning:** Don't characterize a red baseline from a truncated view. Capture the complete failure list first, then attribute — an incomplete list led to a wrong "not my fault" claim that had to be retracted.
