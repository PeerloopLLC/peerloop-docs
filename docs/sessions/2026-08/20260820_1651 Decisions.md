# Conv Decisions - 2026-08-20

## 1. Two-level safety model: commit-safety vs deploy-safety
**Type:** Strategic
**Topics:** testing, cc-workflow, deployment

**Trigger:** `/w-codecheck` had accreted; the user framed intent as "free of errors (hints/warnings)" with a separate "safe to deploy" level.

**Options Considered:**
1. `/w-codecheck` runs everything incl. test+build
2. `/w-codecheck` = fast static commit-safety; `npm run verify` = deploy-safety (+test+build) ← Chosen

**Decision:** `/w-codecheck` = `npm run codecheck` (static, no test/build); `npm run verify` = `codecheck && test && build` (excludes E2E/PLATO).

**Rationale:** Matches "run constantly at commit" vs "safe to deploy". `npm run verify` already existed and maps onto deploy-safety.

**Consequences:** Fixed the false "`/w-codecheck` bundles the 5 gates" claim in CLAUDE.md §Baseline + CLAUDE-OFFLOAD.md; `npm run verify` is now the authoritative baseline command.

## 2. codecheck is a REPORTER, not a fail-fast gate
**Type:** Implementation
**Topics:** cc-workflow, testing

**Trigger:** User: report all issues at all levels; emphasize build-blockers; fix on demand.

**Decision:** `scripts/codecheck.mjs` runs every static check without short-circuit and prints one grouped report — 🔴 build-blockers (CI gates) / ⚠️ local quality gates / ℹ️ warnings — exit non-zero iff a build-blocker or local gate fails (ESLint warnings alone don't fail it).

**Rationale:** A `&&` chain can't report all findings; the build-blocker emphasis is what the user needs for deploy safety.

**Consequences:** `codecheck` npm script → `node scripts/codecheck.mjs`; the `/w-codecheck` skill relays the grouped report and offers fix-on-demand.

**Topics:** cc-workflow, testing

**Options Considered:**
1. Leave grep gates inline in the skill (verify not a superset)
