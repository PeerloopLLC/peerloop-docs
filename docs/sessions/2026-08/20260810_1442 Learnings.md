# Conv Learnings - 2026-08-10

## 1. A rejection's stated reason is the thing to remove, not the thing to argue with
**Topics:** merge-brian, client-work, architecture

**Context:** Three of this client's mechanisms had been formally declined in the MERGE-BRIAN review, and he asked for all three back.

**Learning:** In every case the review's objection was about the *carrier*, not the *design* — raw hex for the colours, a divergent snapshot for the CTA. Adopting them meant fixing the carrier (name the values; share the resolver) rather than overruling the reviewer. This kept the ledger honest and produced a better implementation than either the original rejection or a straight adoption. The reusable move: before re-litigating a declined decision, read *why* it was declined and ask whether that reason can be dissolved.

---

## 2. Sharing a resolver is the only durable fix for two surfaces that must agree
**Topics:** architecture, course-cta

**Context:** The catalog CTA was declined because it disagreed with the detail page for a student with a booked session.

**Learning:** Making the two implementations "match" is not a fix — it is a coincidence with a maintenance schedule. Moving `buildCoursePrimaryCta` into `lib/` and having every surface call it makes divergence impossible *by construction*, and the parity test then fails the moment someone reintroduces a second implementation. The corollary bit twice: each time a new consumer appeared (community tab, teaching flag), the question was "does this go in the shared resolver or the host?", and host-side would have recreated the exact split just closed.

**Pattern:** When a value must be identical across surfaces, share the *function*, not the *value* — and feed it from sources whose predicates are also aligned (`nextSessionId` had to match `computeCourseJourney`'s scheduled-OR-in_progress predicate, not the existing future-only `nextSessionAt`).

## 3. Some defect classes are invisible to every gate
**Topics:** testing, tooling, tailwind

**Context:** Three invented names shipped in one small component — `bg-success-background`, `text-success-700`, `text-text-secondary` — plus `MattIcon name="check"` when no check icon exists.

**Learning:** Tailwind emits nothing for an unknown utility and MattIcon renders a placeholder with a DEV-only warning, so `tsc`, `eslint`, `astro check`, 6,371 tests and `build` were all green while the UI was visibly wrong. Every one was written by following the naming *convention* instead of checking the *catalogue*. A gate for this class is cheap and found 6 more pre-existing defects on its first run.

**Pattern:** When a subsystem fails silently on bad input, the absence of errors is not evidence of correctness — write the check that turns silence into a failure.

## 4. Calibrating a new checker against the real tree is not optional
**Topics:** tooling, heuristic-calibration

**Context:** The token gate's first two runs were both wrong in opposite directions.

**Learning:** An attribute-only scan missed 2 of 6 real violations (class lists here live in variables and object maps, not just `className=`), and once broadened it flagged 4 FALSE positives on a valid `shadow-brian-pill`, because `shadow-*` resolves against `--shadow-*` rather than `--color-*`. Both were reasoning failures invisible until the checker met real code. `[CMH]` exists for exactly this.

---

## 5. A positive test finds inert fixes that a negative test cannot
**Topics:** testing, authorization

**Context:** Widening `recommend.ts` so creators could vouch for students.

**Learning:** Updating the existing negative test's error string would have passed while the feature stayed broken — an *earlier* global "are you a teacher at all" gate rejected non-teaching creators before the widened per-course check was reached. Only a test asserting a creator *can* recommend exposed it. When widening an authorization rule, assert the newly-allowed case, not just the still-denied one.

---

## 6. Testing consumes the fixtures the user needs
**Topics:** process, dev-data

**Context:** The user asked to see the "Send request" state and no student was left in it.

**Learning:** Verifying a one-shot flow end to end *uses it up*. Both completed students had sent their request during my own verification, so the state the user asked to see no longer existed anywhere. For idempotent/one-shot features, either reserve a fixture or plan to reset one — and say so, because the user reasonably assumes the demo data is where they left it.

## 7. Scripted edits to the task board keep going wrong in the same way
**Topics:** editsafe, process

**Context:** Two separate `python3` edits to `CURRENT-TASKS.md` damaged it this conv.

**Learning:** The second was a slice-order bug — `s[:start] + s[end:]` where the body being deleted sat *after* the anchor, so `start > end` and the slice duplicated a region instead of removing one, producing a duplicated body and an orphaned one. It was caught only by `/r-commit`'s task-board gate. `[EDITSAFE]` says use targeted anchored edits on this file; two failures in one conv is the argument for actually doing so rather than reaching for a script.

---

## 8. The dev server bricks on new imports, repeatedly
**Topics:** devserver, tooling

**Context:** The server 500'd three times this conv.

**Learning:** Each time was the documented `[DEVSRV-STALE]` stale Vite dep-optimizer cache (`deps_ssr/resend.js`, `react-chartjs-2.js`), and each was triggered by adding new imports across files — which is what building a feature does. The fix is known and cheap (`astro dev stop` → `rm -rf node_modules/.vite` → restart); the lesson is to expect it after any import-heavy change rather than diagnosing from scratch.

---

## 9. A backgrounded browser lies about computed style
**Topics:** browser-testing, bridge

**Context:** The new pill shadow measured as fully transparent in the DOM.

**Learning:** The Chrome window was backgrounded (`visibilityState: "hidden"`), so the `box-shadow` CSSTransition was frozen at `currentTime: 0` and `getComputedStyle` returned the pre-change value. The CSS was correct throughout. Forcing `element.getAnimations().forEach(a => a.finish())` yields the true settled value. Adds a new variant to `[BRIDGE-OFFSCREEN-WINDOW]`: not just black screenshots, but *stale computed styles* on transitioned properties.
