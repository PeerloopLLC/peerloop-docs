# Conv Learnings - 2026-07-25

## 1. wrangler exact-pin dedupes the miniflare copy — a caret would re-split
**Topics:** cloudflare, dev-tooling

**Context:** MF-SKEW: two miniflare copies at different exact-pinned versions can never dedupe.

**Learning:** wrangler bundles miniflare at an EXACT version; `@cloudflare/vite-plugin` does too. When both pin the *same* version (wrangler 4.112.0 ↔ vite-plugin 1.45.1 both → 4.20260714.0), npm collapses them to ONE shared copy → skew structurally impossible in both read/write directions. A caret (`^4.112.0`) lets a fresh install float wrangler to a version with a *different* mf pin → two copies again → the crash returns. Captured in memory `project_wrangler_exact_pin_miniflare_dedupe`.

## 2. An "optional" peer still ERESOLVE-conflicts when you declare the dep directly
**Topics:** cloudflare, dev-tooling

**Context:** wrangler 4.112's `peerOptional @cloudflare/workers-types@^5` blocked `npm install` even though it's optional.

**Learning:** `peerOptional` means "don't auto-install if absent" — but if the package IS present as a direct dependency (workers-types in `tsconfig types[]`), npm checks it against the peer range and hard-errors on mismatch. The optionality does NOT save you. Options were: bump to v5 (measured tsc-clean → chosen), or a committed `.npmrc legacy-peer-deps=true` (broad, brittle → rejected).

## 3. Mutating node_modules under a running dev server bricks its module runner
**Topics:** astro, dev-tooling

**Context:** The Conv-415 dev server 500'd after MF-SKEW's `npm install`.

**Learning:** `astro dev` (via `@cloudflare/vite-plugin`) loads its miniflare module runner into memory at startup. An `npm install` that swaps those packages on disk leaves the running process with a dead runner → `Cannot read properties of undefined (reading 'get')` 500s on page loads (but CLI `wrangler` ops still work — fresh processes). Always restart the dev server after a dependency change; the ephemeral-dev-server norm (kill when done) exists partly for this.

## 4. Gate UI affordances on the exact criterion the API enforces, not a proxy
**Topics:** testing, ui

**Context:** The "Write a review" button's display criteria.

**Learning:** `POST /course-review` accepts only `enrollment.status === 'completed'` + no existing review. The course page already computes a `courseComplete` *journey proxy* (isComplete OR all-modules-done) that can diverge from the real status. Gating the button on the proxy would show a button whose POST then 400s. Fix: gate on the real `enrollment.status` (a LEFT JOIN in `[...tab].astro`) so display and acceptance always agree. The GET endpoint even exposes a ready-made `can_review` flag with the same logic.

## 5. Headless Playwright needs the client-user cache warmed before deep-linking a client-gated island
**Topics:** testing, plato

**Context:** Verifying the messages `?to=` fix.

**Learning:** `MessagesCenter` calls `getCurrentUser()` client-side and bounces to `/login` (→ Home) if the cache is empty. A cold Playwright context has no cache even with a valid auth cookie, so a direct `goto('/messages?to=…')` landed on Home. Fix: `goto('/')` first (any authed page runs CurrentUserInit and populates the cache), *then* the deep-link — mirroring how a real in-app click arrives. Extends the `[BRIDGE-MEM]` client-gated-island pattern to headless Playwright.

---

## 6. A raw DELETE of a review leaves the course aggregate stale
**Topics:** d1, testing

**Context:** End-to-end review test cleanup.

**Learning:** `POST /course-review` calls `updateCourseRating` (recomputes `courses.rating`/`rating_count`). A manual `DELETE FROM course_reviews` does NOT — so after deleting a test review the aggregate read count=2 vs actual=1. Any raw mutation of review rows must be paired with an aggregate recompute (`UPDATE courses SET rating=(SELECT ROUND(AVG…)), rating_count=(SELECT COUNT…)`), or reseed.
