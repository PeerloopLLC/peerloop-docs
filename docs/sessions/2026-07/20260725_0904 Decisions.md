# Conv Decisions - 2026-07-25

## 1. Adopt Brian's tab COLOURS, not the pill/elevation SHAPE
**Type:** Strategic
**Topics:** design, ui

**Trigger:** Revisiting MERGE-BRIAN mechanism M7 (deferred Conv 409); user wants Brian's tab look.

**Options Considered:**
1. Adopt the full floating-pill treatment (shape + colours)
2. Adopt the colours on our flat tab shape ← Chosen
3. Leave M7 as-is (flat Matt only)

**Decision:** Take Brian's palette as flat tab-state colours; keep our flat rounded shape — the raised-capsule shape stays reserved for badge-like labels of readable text.

**Rationale:** The pill/elevation shape reads as a badge, not a tab (user's call); the colours are the wanted part.

**Consequences:** Only 2 shadow-derived colours become fills; a flat colour→state mapping had to be designed (see Decision 4).

## 2. Persistence = cross-device DB column + instant CSS-var flip (no reload)
**Type:** Implementation
**Topics:** astro, ssr, ui

**Trigger:** Two card precedents already on /profile Preferences — `ThemeToggle` (localStorage-instant) and `LayoutToggle` (DB-reload).

**Options Considered:**
1. Cross-device DB + instant (root attr + CSS vars) ← Chosen
2. Cross-device DB + reload (LayoutToggle clone)
3. Per-device localStorage + instant (ThemeToggle-style)

**Decision:** New `tab_theme` user column, SSR-read → `data-tab-theme` on `<html>`, client flips the attribute instantly + PATCHes in the background.

**Rationale:** Colour is non-structural (unlike nav placement) so it can flip without a reload; the user wanted it to follow them across devices.

**Consequences:** Small schema migration + API validation; FOUC-free via the SSR-set attribute; establishes a reusable user-preference runtime-theme pattern.

## 3. Scope = site-wide (all top-strip tabs via AppLayout), not course-only
**Type:** Implementation
**Topics:** ui, astro

**Trigger:** User: "the tabs on that [/profile] page will be affected."

**Decision:** Set the root attribute in `AppLayout` so every `SubNavItem` tab themes together. `AdminLayout`/`LandingLayout` left on Matt for v1.

**Rationale:** A global preference should restyle all tabs; "/profile tabs affected" rules out course-only. AppLayout covers the whole authenticated app; admin has its own conformance policy and landing lacks SubNav tabs.

**Consequences:** One attribute all tabs read; admin/landing extension is an optional follow-up.

## 4. Flat mapping A "Solid selected"
**Type:** Implementation
**Topics:** design, ui

**Trigger:** "no pill shape" leaves the flat colour→state mapping undetermined.

**Options Considered:**
1. A · Solid selected (solid `#0777b6` chip + white label) ← Chosen
2. B · Underline indicator (accent underline, no fill)
3. C · Soft tint (pale fill + blue label + sky underline)

**Decision:** Mapping A, chosen from a `.scratch/tab-theme-mockup.html` mockup.

**Rationale:** Bold + unmistakable; closest to Brian's intent minus the elevation.

**Consequences:** Uses `#dfe6ee` (hover) + `#102a43` (default label) + existing `#0777b6` (selected) + white; `#2a93d5` added to the guide but unused by tabs.
