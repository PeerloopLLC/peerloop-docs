# Conv Learnings - 2026-07-28

## 1. An off-screen browser window corrupts BOTH scripted behaviour and screenshots
**Topics:** browser-automation, verification, tooling

**Context:** Two separate "failures" this conv — programmatic smooth scrolling being a no-op with throttled re-renders, and a price sticker screenshotting as solid black — turned out to be one cause: the Chrome window was extended past the right edge of the display. The user diagnosed it; I had written the first up as an unfixable harness limitation and was mid-way through mis-framing the second.

**Learning:** `visibilityState: "hidden"` (which an unfocused/off-screen window reports) makes Chrome suppress programmatic smooth scrolling and throttle React re-renders, AND any region past the screen edge captures as flat dark while its DOM is perfectly correct. Check `document.visibilityState` and whether the element's rect exceeds `innerWidth` before concluding "doesn't render" or "doesn't work".

**Pattern:**
The loud-mutation test — force `background:red; width:200px` via JS and re-shoot. If the marker appears, the element paints and the capture was the liar. If pixels stay dark on a correct DOM, ask the user to move the window rather than "fixing" working code.

## 2. Verify against consumers, not string matches
**Topics:** refactoring, premise-checking

**Context:** I reported `formatPrice` as having "11 call sites" from a filename grep. Checking properly showed **6 of the 11 files define their own local `formatPrice`** and never imported the shared one — which is exactly why an admin test asserting `$199.00` kept passing after I changed the shared helper. Real blast radius: 4 consumers, one of them the receipt page.

**Learning:** A grep for an identifier counts *mentions*, not *consumers*. Shadowed local definitions are invisible to it and silently absorb a change you think you're making. The distinction changed the decision — it's what surfaced the receipt as needing a cents-preserving carve-out.

**Pattern:**
```bash
for f in $(grep -rl NAME src/); do grep -qE "^(export )?function NAME|const NAME *=" "$f" && echo "LOCAL: $f" || echo "SHARED: $f"; done
```

## 3. A plan document's own inventory can be stale — re-derive before costing work
**Topics:** planning, premise-checking

**Context:** My §2 inventory described M11 as "cheap — reuse the `CommunityBand` primitive we already built in Conv 410". `CommunityBand` does not exist: Conv 410 landed `[COMM-BAND]` as **inline markup inside `CourseHeader`**, and the community join lived only in the course-detail loader. The real work was extracting a component plus adding the chain to the browse loader.

**Learning:** A prior conv's "BUILT" note records that an *intent* shipped, not the *shape* it shipped in. When an inventory entry says "reuse X", confirm X is a thing before estimating from it.

## 4. Switching a component to a new variant strands the old path silently
**Topics:** dead-code, orphan-detection

**Context:** Moving `/courses` to the new `cover-story` variant left `stacked + context="catalog"` with no caller, so every `isCatalog` branch and the `sessionCount`/`durationLabel`/`creatorAvatarUrl` props feeding them became unreachable — while tsc, lint and 6155 tests all stayed green.

**Learning:** Same shape as `[ORPHAN-DETECT]` for routes, one scale down: a variant switch is a silent orphan-maker, and the gates cannot see it. After changing which variant a call site requests, re-enumerate the call sites and check what the old branch still serves.

## 5. A disposition can be unbuildable as written
**Topics:** planning, scope

**Context:** M10 was dispositioned "ADAPT — share the cover panel, keep our hero". Our hero renders course art as a full-bleed dark backdrop with white text over a scrim: there is no cover panel to share, and giving it one removes the dark ground the text depends on, turning it into the card — the option the walk had explicitly declined.

**Learning:** A disposition chosen from a menu can encode two requirements that cannot both hold once you look at the implementation. Surfacing it as under-specified and re-asking cost one question; guessing would have either reworked the Conv-413 hero uninvited or shipped a token gesture and called the mechanism done.

## 6. `flex-wrap` cannot push a sibling onto its own row
**Topics:** css, layout

**Context:** Fixing the 375px title cramp, the obvious fix was `flex-wrap` on the title row so the CTA would drop below.

**Learning:** Flex items **shrink before they wrap**, so the `h3` would keep being squeezed and the button would never move. Forcing a specific element onto its own row at a breakpoint needs an explicit direction change (`flex-col … @xl:flex-row`), not wrapping.

## 7. A `<select>` silently rejects a value with no matching option
**Topics:** testing, browser-automation

**Context:** Probing the new mobile Topic select, `setter.call(sel, 'topic-ml')` left `sel.value === ""` and nothing published — which looked like a broken control. `topic-ml` was an ID from my **unit-test fixtures**; the live DB uses `top-001`.

**Learning:** Setting `.value` to a value no `<option>` carries yields `""` with no error, so a "control doesn't work" conclusion can be a bad test value. Read the real options off the element first. The discriminator that caught it: run the identical trick on a control known to work (Level published fine, Topic's value didn't even stick → the value, not the wiring).

## 8. `elementFromPoint` skips `pointer-events:none` elements
**Topics:** browser-automation, dom

**Context:** Hit-testing the price sticker returned the content row, not the sticker — which I nearly read as occlusion.

**Learning:** The sticker is deliberately `pointer-events-none` so it can't eat the card's stretched link, and hit-testing ignores such elements by design. A miss proves nothing about paint order; temporarily restore `pointerEvents = 'auto'` to ask the real question.

---

## 9. Register newly-stamped components on landing, or the provenance gate creeps
**Topics:** provenance, tooling

**Context:** Three new components stamping `data-prov-name` took `prov:sweep` from its documented 11 issues to 17. `[PROV-SWEEP-DEBT2]` predicts exactly this ("the gate drifts by one every time a stamped component ships unregistered").

**Learning:** The debt grows one component at a time precisely because each individual omission is invisible against an already-red gate. Registering on landing is the cheap habit; the self-audit only caught it because the count was checked against the documented baseline rather than eyeballed.

---

## 10. Write empty-state copy against an invariant, not a list of filter flags
**Topics:** ux-copy, correctness

**Context:** The `/courses` empty state branched on `q` and `availableSoon`, so topic/level/length narrowing to zero announced "No courses available right now." — claiming an empty platform.

**Learning:** Enumerating filter flags in the copy condition means every new filter silently re-opens the bug. Keying off the invariant instead — with no filters applied `allVisible` is `courses` re-sorted, so `courses.length === 0` is the only genuine nothing-published case — makes the platform-empty message unreachable by any filter, present or future.

## 11. A wrapper primitive can nest the forms plugin's own chrome inside itself
**Topics:** css, tailwind, primitives

**Context:** `@tailwindcss/forms` is active. Our `Select` stripped its chrome in Conv 223 `[DRV-C]`; `Input` never got the twin, so the wrapper's border + `px-16 py-12` sat outside an inner `<input>` carrying its own 1px border and 8px/12px padding — a visible box-in-a-box on every form.

**Learning:** It also made the new `compact` prop unachievable (49px where ~34px was intended), so a cosmetic prop was blocked by an unrelated latent defect. When a density prop doesn't produce its stated height, measure the inner control before adjusting the wrapper.
