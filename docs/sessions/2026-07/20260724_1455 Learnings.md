# Conv Learnings - 2026-07-24

## 1. Verify a component's history before calling it "meaningless"
**Topics:** provenance, migration, cc-workflow

**Context:** I characterized the empty Matt `ResourcesTab.astro` as an "always-empty placeholder" fit to delete. The user pushed back ("It wasn't always empty, was it").

**Learning:** The Matt component had *always* been an empty stub — but that stub was a **functional regression** from a working pre-flip `ResourcesTabContent.tsx` (242 lines) that rendered files. "The current component never rendered data" ≠ "the page never showed data." Before retiring/superseding a surface, check git `--follow` history AND the pre-flip worktree AND whether the data/API/management-UI still exist — a stub can be a half-finished regression, not dead weight.

**Pattern:**
`git log --follow`, read the pre-flip worktree version, and check whether the read-API + seeded data still exist before concluding a feature is absent.

## 2. Parity-diff the deleted implementation before removing a regressed surface
**Topics:** migration, testing, cc-workflow

**Context:** M3 re-surfaced resource data on the Modules tab; the user asked whether anything from the deleted Resources view was now missing.

**Learning:** A field-by-field diff against the deleted `ResourcesTabContent.tsx` found two real gaps (per-file descriptions, role-aware visibility) that M3 had silently dropped — exactly the `feedback_port_functionality_and_styling` DISC-DROP failure. Retiring a regressed surface is only safe once the replacement is a proven *superset*, established by an explicit diff, not by eyeballing.

**Pattern:**
When replacing a surface, enumerate the deleted version's features as a checklist and confirm each is covered (or consciously dropped with a reason) before deleting.

## 3. Provenance marker detection must match a declaration, not a substring
**Topics:** provenance, docs-infra

**Context:** Regenerating `matt-sourced-registry.generated.ts` after deleting a component added a *false* entry for `messages/matt/Avatar.tsx`.

**Learning:** `gen-registries.ts`'s `/@matt-source\s+\d+:\d+/` regex matches the marker-with-node **anywhere** in a file, including prose. `Avatar.tsx` (genuinely `@matt-inspired`) names the UserIcon node it wraps ("@matt-source 1:35") in its docstring → falsely registered as matt-sourced, producing 3 phantom sweep errors. A marker scanner must require the marker to be a standalone provenance declaration (align with `prov-sweep.ts`'s accept-rule), not a bare substring.

**Pattern:**
Fixed for the live instance by rewording the prose; the durable scanner fix is tracked under `[PROV-SWEEP-DEBT2]`.

## 4. Non-null-href guard structurally kills the dead-link class
**Topics:** astro, d1

**Context:** Brian's `fileHref = external_url ?? null` rendered every R2 upload as a clickable dead link.

**Learning:** Resolving each file to a **guaranteed non-null href** in the loader — upload → download route, external → its URL, neither → *dropped* — makes a dead link structurally impossible rather than relying on the template to guard. The `external` flag then drives same-tab-download vs new-tab-open.

**Pattern:**
```ts
const href = r.r2_key ? getResourceDownloadUrl(r.id) : r.external_url;
if (!href) return null;
```

## 5. A prior conv's "5 gates green" is a hypothesis, not a fact
**Topics:** testing, cc-workflow

**Context:** `tsc --noEmit` flagged a `TS2367` at `courses.test.ts:412` — code committed in Conv 411, whose build log claimed all 5 gates green.

**Learning:** Confirmed red at clean HEAD via `git stash` + tsc. Conv 411's baseline claim was inaccurate (tsc against tests was evidently not run, or its failure missed). Reinforces §Baseline Verification Rule 2: re-verify in *this* conv before trusting; a carried-forward "green" is a hypothesis.
