# Conv Learnings - 2026-07-25

## 1. Opacity-dim hover is imperceptible on a pale-on-white button
**Topics:** ui-ux, astro, hover

**Context:** Standardizing the Modules-tab / sticky-CTA hovers; `hover:opacity-90` on the pale-green `variant="course"` CTA produced no visible change.

**Learning:** Dropping opacity blends an element *toward the page background*; on a colour that is already near-white (pale green on white), the shift is invisible. Pale "tonal" buttons need a COLOUR hover (darken the bg), not an opacity dim. Solid/dark buttons dim fine with opacity. Confirmed via DOM (`getComputedStyle` bg unchanged, opacity 1→0.9).

**Pattern:** For a pale course CTA: `transition-colors hover:bg-course-primary/20 hover:border-course-primary/20` (darken one step, keep dark text) — variant-aware so darker variants keep `hover:opacity-90`.

## 2. The Button primitive has no CSS :hover at property1="Small"
**Topics:** matt-design-system, ui-ux

**Context:** The sticky "Go to Session" CTA (`SubNav.astro:247`) showed no hover feedback.

**Learning:** `ui/Button.tsx` only draws hover for the Figma `property1="Hover"`/`"SmallHover"` *state* (hardcoded, primary-only); at `property1="Small"` (what SubNav passes) there is NO CSS `:hover` at all — the base class is just `transition-opacity`. Any hover feedback on a Button-primitive usage must be added via `className` at the call site (proper variant-aware hover is deferred Phase-6 [MATT-EXEC-EXT] work).

## 3. [MF-SKEW] wrangler CLI ↔ astro dev share Miniflare state; version skew breaks the older tool
**Topics:** cloudflare, dual-repo, cc-workflow, deployment

**Context:** `db:seed:r2:local` crashed against a running dev server with `table _cf_ALARM has 3 columns but 2 values supplied`.

**Learning:** Both `wrangler … --local` and `astro dev` (`@astrojs/cloudflare` → `@cloudflare/vite-plugin`) run Miniflare, persisting to the same `.wrangler/state/v3` SQLite files (incl. an internal `_cf_ALARM` table). wrangler bundles miniflare **4.20260521**, the dev server **4.20260714** — the newer migrated `_cf_ALARM` 2→3 columns ON DISK, so the older wrangler crashes opening it (forward-incompat). It's a persisted-schema conflict, not a live lock: **stopping the dev server is necessary (it re-upgrades the schema on any access) but NOT sufficient (the on-disk schema stays upgraded)** — recovery is `rm -rf .wrangler/state/v3` then reseed with no dev server up. R2 puts survive longer than D1 execute (D1's local emulation touches the alarm store first).

**Pattern:** Interim: stop `astro dev` before any `wrangler --local` op (the standard flow — setup before starting dev — is unaffected). Durable: align the two Miniflare versions.

## 4. Dev R2 is empty — SQL seed inserts resource metadata but never uploads blobs
**Topics:** cloudflare, d1, testing

**Context:** Course-file downloads 404'd → the browser saved the JSON error as `download.json`.

**Learning:** `migrations-dev/0001_seed_dev.sql` inserts `session_resources` rows with an `r2_key`/size/mime, but SQL can't PUT to R2, so local R2 has 0 objects and `/api/resources/:id/download` returns `404 {"error":"File not found in storage"}`. The `download` attribute then saves that JSON as a phantom file. Fix: a dev script (`scripts/seed-r2-dev.mjs`) PUTs a type-appropriate placeholder (valid blank PDF / empty ZIP / text) per `r2_key`, wired into `db:setup:local:dev`.

## 5. Aligning wrangler's Miniflare drags in a major @cloudflare/workers-types bump
**Topics:** cloudflare, deployment, cc-workflow

**Context:** `npm i -D wrangler@latest` failed on a peer conflict.

**Learning:** wrangler 4.114 (miniflare 4.20260722, schema-compatible with the dev server's 714) peer-requires `@cloudflare/workers-types@^5.x`; the project is on **v4**, and that package sits in `tsconfig.json`'s global `types` array → a major bump reshapes type-checking codebase-wide. Also a **global nvm wrangler 4.58** shadows the project's `node_modules` 4.94 on PATH, so alignment must address both. Lead for the focused task: find a wrangler in 4.95–4.113 whose miniflare ≥ 4.20260714 but that still peers workers-types v4.
