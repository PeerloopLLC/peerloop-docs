# Conv Learnings - 2026-07-28

## 1. A task's recorded blocker is a claim, not a fact — and this now has a track record
**Topics:** process, premise-testing, planning

**Context:** `[ROLE-CRS-LIST]` was scoped as "build teaching + moderating course lists", blocked for two convs.

**Learning:** Four of five load-bearing claims were false when checked against **consumers**: `TeacherDashboard` already rendered a course list off the *same* array the tab counted from; `/teaching/sessions` grouped by course too; the cited "no courses LIST page" comment was about the **route**, not page content; `#moderating` was community-scoped and already homed. The gate also silently omitted a fourth lens. Re-testing collapsed two new pages into one component upgrade. This is the third consecutive conv where the pattern paid (`[REC-REHOME]` 427, `[ROLE-CRS-LIST]`/§5 428).

**Pattern:** Before building a prerequisite, check the claim against the code that *consumes* the thing, not the definition or the comment that describes it.

## 2. A unit's recorded scope is a claim too — census, don't trust the map
**Topics:** process, planning, merge-brian

**Context:** §4 was mapped as 11 files; §5 as a feature decision.

**Learning:** §4 was 4 live mechanisms (7 files already dispositioned by earlier walks). §5 had **no open decision at all**. And `api/sessions/index.ts` sat in §5 but was teacher switching. Mis-filing is normal across a long programme.

**Pattern:** The census is authoritative, not the route-impact map. Verify each mapped item against the tree before treating it as work.

## 3. Exclusion globs silently swallow siblings
**Topics:** tooling, bash, process

**Context:** A completeness sweep excluded `migrations` and therefore also `migrations-dev/`.

**Learning:** The dev seed is the actual data source for `/courses` in dev, so adopting the cover SVGs in `seed-feeds.mjs` + `mock-data.ts` alone would have been a **no-op in dev**. Caught only by re-reading his diff for §6.

**Pattern:** When excluding a path prefix in a sweep, check whether sibling directories share it (`migrations` vs `migrations-dev`).

## 4. A green gate that is permanently red is worse than no gate
**Topics:** tooling, quality-gates, provenance

**Context:** `prov:sweep` had sat at 11 issues since Conv 416; this conv reported it as "at baseline" eight times.

**Learning:** A red gate cannot detect a *new* offender — which is its whole purpose. Conv 425 proved it: three newly-stamped components took it 11→17 and it went unnoticed until an unrelated self-audit. All 10 errors were the same trivial shape (stamped, unregistered).

**Pattern:** Never normalise a failing gate as "baseline". Either fix it or disable it — a red gate that is routinely reported as expected is a detector that has been switched off without anyone deciding to.

---

## 5. Removing a control can strand users if its entry points outlive it
**Topics:** frontend, routing, verification

**Context:** Removing the `/courses` role tabs left `CoursesCatalog`/`CoursesFilters` still reading the URL hash.

**Learning:** `/courses#teaching` rendered the teaching lens with **no control to leave it** — 0 catalog cards from a stale bookmark. Only live verification found it; all five gates were green.

**Pattern:** When deleting a UI control, enumerate every *other* way its state can be entered (hash, query, event, deep link) and neutralise them in the same change.

---

## 6. Two workspaces solving the same problem differently is a defect, not a style difference
**Topics:** frontend, roles, ux

**Context:** `useCreatorGate` guarded all five `/creating` islands; `/teaching` and `/learning` had no equivalent.

**Learning:** A signed-in non-teacher on `/teaching` got a red "Teacher access required" box and a **Retry that can never succeed**, under a header promising earnings. `/creating` showed a graceful gate with an application path. This mattered beyond consistency: `/teaching` is where the flywheel recruits, so the error was shown to exactly the students it wants to convert.

**Pattern:** When comparing sibling surfaces, look for the *absent* mechanism, not just the differing one.

---

## 7. Anchor uniqueness is not anchor correctness
**Topics:** editsafe, process

**Context:** Five "Done this conv" records were anchored on strings that happened to live inside the `[MERGE-BRIAN-JULY7]` task body.

**Learning:** Closing the task deleted them. Caught only because the Done block came back with 6 entries instead of 11.

**Pattern:** `[EDITSAFE]` — verify the anchor is in the intended *section*, not merely unique in the file.

---

## 8. A disposition can be unbuildable as written
**Topics:** process, merge-brian

**Context:** "Rehome `CourseCreatedCard` into `CreatorStudio`" looked like the twin of the `/learning` swap.

**Learning:** It takes `UserCreatedCourse` while the studio's card takes `CourseWithStats` **plus** an `onEdit` handler; swapping would drop the level badge, topic, module count, price and the in-place edit modal (its "Edit" is a link back to the studio — circular from inside it). Same shape as §2's M10.

**Pattern:** Surface the impossibility with the specific losses named; do not silently substitute a lesser change.
