# Conv Decisions - 2026-07-26

## 1. Classify a labelled nav row as standalone, not inline
**Type:** Implementation
**Topics:** icon-system, design-tokens

**Trigger:** Migrating AdminNavbar's 17 menu glyphs required choosing an icon family, and the standard's own examples pull both ways — "beside text → inline" by geometry, but "nav-rail icon" is listed as a *standalone* example.

**Options Considered:**
1. Inline em (`size-icon-inline-lg`) — honours the beside-text geometry rule
2. Standalone rem (`size-icon-20`) ← **Chosen**
3. Add a 4th inline step / re-anchor the em ladder

**Decision:** Nav rows with labels use the standalone rem family.

**Rationale:** AdminNavbar's labels are `text-body-small` = 12px, where the em ladder reaches only 13.8px (`md`) or 17.4px (`lg`) against today's 20px — it cannot express the shipped size at all. `[ADMIN-CONF-POLICY]` also makes the admin label deliberately small, which is a poor thing to chain a glyph's size to. Standalone rem is visually neutral and treats a nav glyph as a fixed affordance.

**Consequences:** 17 sites migrated neutrally. Also produced the first real answer to the block's open question about em ratios — the three inline steps are anchored on 14px body text and **do not serve a 12px label**. Recorded as a workaround rather than a fix: a genuine 12px-label inline icon still has no home, and tranche 3b is likely to force the question.

## 2. Narrow `icon-no-size-class` and re-baseline, separating correction from migration
**Type:** Implementation
**Topics:** tooling, icon-system

**Trigger:** All 46 of the rule's reported sites were false positives, so its true count was zero.

**Options Considered:**
1. Leave the 24+ false positives in the baseline and migrate around them
2. Narrow the rule via a structural pre-pass and re-baseline ← **Chosen**

**Decision:** Rule asks whether there is provably no sizing input *anywhere* — call site or component — via `selfSizingIcons()`.

**Rationale:** Left in place, the false positives would resurface in every future tranche's triage. A structural pre-pass was preferred over a hand-maintained allowlist because the latter rots silently as components are added.

**Consequences:** Baseline dropped 46 from the correction. Recorded **separately from the 200 genuine migrations** in the plan and both commits, so the number can never later read as more progress than it was. Verified by injecting a genuinely unsized probe component (caught, exit 1, +1 violation) before removing it.

## 3. Repair `ModeratorInvite` wholesale, crossing into the spacing scale
**Type:** Strategic
**Topics:** icon-system, tailwind, legacy-migration

**Trigger:** The component renders an 8×8px glyph in a 16×16px circle on an 8px-padded card — a user-facing defect on the moderator-invite error/success/declined states — and the icon axis alone could not fix it.

**Options Considered:**
1. Fix the whole component ← **Chosen**
2. Log it as its own task, keep the block strictly on the icon axis
3. Icon only, accepting the overflow
4. Also un-park `BecomeATeacherPage` and close the class entirely

**Decision:** Convert the whole component to the codebase's literal-px convention, including spacing.

**Rationale:** Option 3 would have looked worse than today (32px glyph in a 16px container). The Conv-419 standard deliberately excluded `p`/`m`/`gap`, so this crosses a stated boundary — but the blast radius was measured first and is bounded: 7 files use the v3-era palette, only 2 carry overridden icon classes, and the second is already parked.

**Consequences:** 90 classes converted; re-measured at 64×64 circle / 32×32 icon / 32px padding. Recorded in the plan with the authorising decision attached, so the exception is traceable rather than looking like scope drift later. Only the error state was live-verified.

## 4. Ask before running `/r-end` despite a "wrap up" selection
**Type:** Implementation
**Topics:** cc-workflow

**Trigger:** The user selected an option labelled "Stop here / wrap up", which implies ending the conv.

**Options Considered:**
1. Treat the selection as approval and run `/r-end`
2. Do the non-destructive teardown, then ask explicitly ← **Chosen**

**Decision:** Performed dev-server teardown and clean-state verification, then asked explicitly.

**Rationale:** CLAUDE.md § Conv Lifecycle singles out `/r-end` as always needing explicit approval; the selected option did not name it. The independent work was done first so the question was the last thing in the turn.

**Consequences:** One extra exchange; rule honoured.
