# Conv Learnings - 2026-07-27

## 1. A repeatedly-dodged question may not be load-bearing — check before answering it
**Topics:** design-tokens, decision-making, process

**Context:** The "532 non-icon bare-numerics — whose axis?" question had been open since Conv 420 and was framed as needing an answer (own axis / arbitrary-px sweep / permanent carve-out). It was the second such question in this block: the `em` ratios question was dodged three times before Conv 421 dissolved it by rescinding the family.

**Learning:** Both questions were resolved by **removing their premise**, not by choosing an option. The 532 stopped being a defect when the base multiplier made every number self-describing. When a question has been deferred several times, that is evidence worth acting on — test whether it is load-bearing before spending effort answering it.

**Pattern:** Before answering a long-open design question, ask "what would have to be true for this question to disappear?" and cost that path alongside the listed options.

## 2. Scoping a rejected option can surface the option you actually want
**Topics:** tailwind, design-tokens, measurement

**Context:** The plan named "rename the `--spacing-*` override" as the deeper fix but nobody had costed it. Scoping priced it at 4,911 sites / 295 files — clearly too big.

**Learning:** The measurement that killed the option produced the winning one. The 4,911-vs-361 ratio showed the exception was the *un*-overridden numbers, which pointed at the base multiplier — a one-line change nobody had considered because the framing was always "which call sites do we sweep?". The scoping exercise was worth doing even though its stated answer was "no".

**Pattern:** When costing an option you expect to reject, look at the distribution the count came from, not just the total.

## 3. Predict a number before trusting the tool that produced it — three more instances
**Topics:** measurement, tooling, verification

**Context:** Carried in from Conv 422's Key Context; fired three more times this conv.

**Learning:** (a) The blast-radius scan matched `%Y-%m-01` in SQL date strings as `m-01` and `"top-001"` topic IDs as `top-N` — 12 false positives, caught because zero-padded numbers are never Tailwind classes. (b) The diff verifier paired removed lines with the physically next line, which desynchronises the moment a `-U0` hunk removes two lines in a row — the same index-pairing defect Conv 421 hit in `tokened-did-not-scale`. (c) The live scanner reported 184 mismatches that were every one a variant-shadowed element (`px-16` alongside `lg:px-32`). Each was caught by the number looking implausible, never by re-reading the code.

**Pattern:** State the expected magnitude out loud before running a new instrument. All three failures were visible as "that number is wrong for this codebase" within seconds.

## 4. Verify an edit with an instrument that shares no code with the one that made it
**Topics:** verification, tooling

**Context:** The 449-site sweep reported its own edit count, which is exactly the number a buggy sweep would also report confidently.

**Learning:** The verifier parses the **git diff** — not the sweep's report, not the source — and re-derives that every changed class is exactly `N → N×4` with no other text altered on the line. That independence is what makes "449 of 449" meaningful. It also caught its own pairing bug, which a shared-code verifier would have inherited silently.

## 5. Tailwind v4's base `--spacing` is a single multiplier, and named entries bypass it
**Topics:** tailwind, astro, design-tokens

**Context:** Verified empirically by compiling the project's real stylesheet, not read from documentation.

**Learning:** Un-named numbers compile to `calc(var(--spacing) * N)`; declaring `--spacing-N` in `@theme` creates a named entry that bypasses the base for that number only. So overriding ten names (Conv 174) fixed ten numbers and left the rest on the stock `0.25rem` — which is what produced two meanings for one syntax. Setting the base itself is strictly more powerful than any number of named overrides, and covers numbers not yet written.

**Pattern:** `--spacing: 0.0625rem` makes N mean N px universally, and every existing named token remains exactly correct because each was already `N × 0.0625rem`.

---

## 6. A value-preserving transform can be proven without a before-run
**Topics:** verification, measurement

**Context:** Verifying 449 rewrites normally means capturing "before" measurements to diff against.

**Learning:** Choosing the rewrite so that the *new* value equals the old one by construction (`N×4 × 0.0625rem ≡ N × 0.25rem`) converts the check into a single invariant — "does `X-N` measure N px?" — that needs no baseline. One live scan then proves both the root change and all 449 edits at once.

## 7. Widening a sweep's file set is a distinct decision from widening its regex
**Topics:** tooling, refactoring

**Context:** Two gaps nearly shipped: 5 `@apply` sites in `global.css` (wrong *file type* — the sweep walked `.tsx/.jsx/.astro`) and 95 fractional utilities (wrong *token shape* — the regex rejected a trailing `.`).

**Learning:** They are independent failure axes and neither is visible from the other. The measurement that says "361 sites" is only as complete as the file set *and* the pattern that produced it — a sweep that reconciles perfectly against its own scan can still miss a whole category.
