# Conv Learnings - 2026-07-26

## 1. A task premise written from reading the function does not survive contact with the call sites
**Topics:** process, task-authoring, verification

**Context:** Four separate task premises were falsified this conv, all the same way. `[CANMSG]` said the client gate was vacuous (it wasn't, on 3 of 4 surfaces). `[MSG-ADOPT-A]` said to thread `signedIn` through (the components had no viewer knowledge). `[MSG-ADOPT-B]` prescribed `appearance="bare"` for all 10 (3 needed the `Button` chrome). `[COURSETAB-HASH]` named the wrong root cause entirely.

**Learning:** Every one was written by reading the *implementation* rather than enumerating the *consumers*. Re-test a task's premise before executing it — the check is cheap and the four hits were all material.

**Pattern:** Before executing a task written in a prior conv, spend one tool call enumerating its actual call sites. Treat the task body as a hypothesis.

## 2. Grep answers "what is written"; only measurement answers "what renders"
**Topics:** css, tooling, verification

**Context:** `[ICON-4PX]` was scoped from `grep h-4 w-4` → "44 sites". Measuring live DOM across 18 routes found `h-8 w-8` avatars at 8px that the grep never saw, and the sourcemap oracle later found 3 more dead files the route detector missed.

**Learning:** For any claim about rendered output, the source text is a proxy and the DOM (or the bundler) is the fact. Three separate scope errors this conv came from trusting the proxy.

**Pattern:** DOM-measure across routes at two root font sizes; read sourcemap `sources` rather than grepping minified output.

## 3. The three-state hydration race is a recurring class, not an incident
**Topics:** react, astro, auth

**Context:** `[MSGBOOT]` (Conv 417) fixed `MessagesCenter` + `useCanMessage`. `[COURSETAB-HASH]` (this conv) was the identical bug in `useRoleTabs`: an effect reading "not yet resolved" as "no".

**Learning:** Any consumer deriving state from `useCurrentUser()` without gating on `useAuthStatus()`'s third state has this bug latent. It presents differently each time (bounced to `/login`; zero affordances; a discarded deep-link tab), which is why it keeps reading as a new problem.

**Pattern:** `if (authStatus === 'loading') return;` — or a `ready` prop the caller passes — before any effect that decides something from user-derived data.

## 4. A noisy rule is worse than no rule
**Topics:** tooling, verification

**Context:** The `icons:scan` `inline-ratio` check first keyed off "is there text nearby" and produced 38 findings, nearly all course thumbnails, 48px avatars and empty-state illustrations.

**Learning:** Re-keying on geometry — does the icon *vertically overlap* its text (beside) or not (stacked above) — took false positives to zero. A checker that cries wolf gets ignored, which is the same failure the new-violations-only baselining exists to prevent.

## 5. Dead code is invisible to every green gate, and it compounds
**Topics:** dead-code, tooling, process

**Context:** 5 of 43 icon fixes landed on unreachable files — hitting `TestimonialsBrowse`, the same file Conv 404's `[A11Y]` batch wasted a fix on. The 53 orphans also inflated the `[ICON-TOK]` baseline by 169 violations (10%).

**Learning:** tsc, lint, tests and build all stay green over dead code, so it looks alive to every tool and to every sweep. The cost is recurring and compounding: wasted edits, inflated censuses, and noise that trains people to skip the detector.

**Pattern:** Run the reachability check over any batch *before* editing it — and prefer deleting dead code to parking it, unless the parking has a dated, concrete consumer.

---

## 6. Barrels defeat import-graph reachability in both directions
**Topics:** dead-code, tooling, bundler

**Context:** knip found 14 orphans; the route detector found 53; the bundler found 56.

**Learning:** A **dead** barrel keeps its re-exports "alive" for knip (`marketing/index.ts` kept `FaqPage`). A **live** barrel with an unconsumed re-export hides dead files from route-reachability (`admin-intel/index.ts` hid 3). Only the bundler resolves both, because tree-shaking is the question being asked.

**Pattern:** Temporarily enable `vite.build.sourcemap`, build, union the `sources` arrays of every `dist/**/*.map`, restore. ~2 min, immune to minification and barrels.

---

## 7. Building the measuring instrument after the change measures nothing
**Topics:** process, verification

**Context:** `icons:scan` was built in the same conv as the 43-site icon change it was designed to catch regressions in — so its baseline already contains that change.

**Learning:** A baseline captured after the fact cannot answer "did this change break anything". The tool is still useful going forward, but the change that motivated it went unverified against a before-state.
