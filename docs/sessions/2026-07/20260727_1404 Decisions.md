# Conv Decisions - 2026-07-27

## 1. Fix the numeric-spacing ambiguity at the base multiplier rather than at call sites
**Type:** Strategic
**Topics:** tailwind, design-tokens, astro

**Trigger:** Phase 6's second item — deciding the fate of the 532 `dimension-bare-numeric` sites — with the plan itself naming a `--spacing-*` rename as "the deeper fix this block only works around".

**Options Considered:**
1. Own token axis for boxes — ~439-site multi-conv sweep, leaves the trap for new code
2. Arbitrary-px sweep — mechanical, recreates the `icon-arbitrary-px` shape Conv 421 just retired
3. Permanent carve-out — cheapest, ambiguity stays in the code
4. Scope the root fix first ← **Chosen**, and it led to setting the base multiplier

**Decision:** Set Tailwind v4's base `--spacing` to `0.0625rem` so every number means its own pixel count, and rewrite the 449 call sites that relied on the ×4 reading as `N → N×4`.

**Rationale:** Options 1–3 all fix today's sites and none stop the next one — `h-16` would still mean 16px for every line written afterwards, which is precisely why Phase 6 needed a lint rule at all. The base fix covers numbers nobody has typed yet, which no call-site sweep can reach. It was provably safe before being applied: one line differs in 185 KB of compiled CSS.

**Consequences:** The defect the entire ICON-SIZING block was built to work around no longer exists. The 532 informational sites and the 25 governed ones stop being ambiguous. Phase 6's lint rule became unnecessary. Two of the block's long-open questions closed.

> **Insight:** A rule that has to be enforced at every future call site is usually a symptom of a mis-set default one level down. Costing the "too big" option is what exposed the distribution — 93% of numeric spacing already meant literal px — that made the default, not the call sites, the real defect.

## 2. Retire the `dimension-bare-numeric` informational tier outright
**Type:** Implementation
**Topics:** tooling, design-tokens

**Trigger:** After the root fix, the tier measured a non-defect.

**Options Considered:**
1. Leave it reporting 532 as a measurement
2. Zero it but keep the rule
3. Delete the rule and omit the baseline key ← **Chosen**

**Decision:** Remove the rule; `INFORMATIONAL` is an empty set and the baseline omits the `informational` key rather than writing `{}`.

**Rationale:** An empty object reads as "a tier exists and is clean", which would be false — the tier was retired, not emptied. Keeping the mechanism (an empty set) preserves warn-first adoption for a future rule, which is how this project has landed every other lint set.

**Consequences:** `check:icons` reports 25 governed violations in one file and nothing else. The 93 `min-w-0` sites that were never ambiguous disappear with it.

## 3. Cancel Phase 6's bare-number lint rule deliberately
**Type:** Implementation
**Topics:** tooling, cc-workflow

**Trigger:** Its stated purpose was making the ambiguity editor-visible while typing.

**Options Considered:**
1. Ship it anyway for readability
2. Cancel and record why ← **Chosen**

**Decision:** Cancelled, marked `[x]` in the plan with the reasoning, not silently dropped.

**Rationale:** There is no ambiguity left to surface; the rule would flag correct code for a defect that cannot occur. What remains — "a bare number does not *name* the icon axis" — is already covered by `check:icons` and is not worth editor-level enforcement.

**Consequences:** Phase 6 reduces to the warn→error promotion, still gated on `[RG-PUBLIC]`.

## 4. Keep the `--icon-N` token family as-is
**Type:** Strategic
**Topics:** design-tokens, cc-workflow

**Trigger:** The root fix made the family behaviourally redundant — `size-icon-16` and `size-16` now compute to the same 1rem, and `--icon-N`/`--space-N` are identical at every overlapping step.

**Options Considered:**
1. Keep as-is ← **Chosen** (user)
2. Keep but freeze — tokens as documentation, no further migration, drop the warn→error ambition
3. Retire — ~600 mechanical `size-icon-N` → `size-N` edits, plus deleting 11 tokens and the checker

**Decision:** Keep the family and the gate unchanged.

**Rationale:** Decided on asymmetry rather than enthusiasm. The family is the only surviving record of *which elements in this codebase are icons* — information that took four convs to produce and is encoded nowhere else (components take a bare `className` for icons and boxes alike; not in the DOM, not in the types). Retiring is cheap to do and expensive to undo, and it is the seam that would make a future icons-only scaling change a one-line edit. The drawbacks are real and evidenced — two vocabularies for identical values force an "is this an icon?" judgment that has been wrong before — but reduce to "a convention needs discipline".

**Consequences:** `check:icons` keeps its 25-site gate and its path to zero. The rule messages were reframed to state a readability rationale rather than a (now false) mis-render claim.

> **Insight:** When a classification layer becomes behaviourally redundant, its remaining value is as *recorded knowledge*, not as enforcement. The asymmetry test — cheap to remove, expensive to reconstruct — is the right one for any layer whose only output is information nothing else encodes.
