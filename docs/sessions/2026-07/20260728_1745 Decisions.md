## 2. `[BACK-X]` — keep breadcrumbs, drop the back button, take the sticky title
**Type:** Strategic
**Topics:** navigation, ux, merge-brian

**Trigger:** Client-flagged watch area; user asked whether the button duplicated browser Back.

**Options Considered:**
1. ADOPT as-is (breadcrumbs gone site-wide)
2. ADAPT — back row + breadcrumbs
3. ADAPT — drop the button, keep the sticky title ← **Chosen**
4. DROP entirely

**Decision:** Breadcrumbs kept; back button dropped; sticky title taken as `StickyViewTitle`.

**Rationale:** The handler is literally `history.back()` and renders desktop-only, where the browser's Back is always visible; its one non-duplicate case is covered by the breadcrumb we kept.

**Consequences:** New component on 3 deep pages; his site-wide breadcrumb removal not adopted.

## 3. `[FEED-WIDTH]` dropped — geometry and rails stand or fall together
**Type:** Strategic
**Topics:** layout, product-metrics

**Trigger:** User questioned why a course page would advertise other courses.

**Options Considered:**
1. 640px + rails on course detail
2. 640px geometry only
3. DROP ← **Chosen**

**Decision:** Course detail stays full-width.

**Rationale:** The only candidate filler was `DiscoveryRails`, whose value splits by enrolment — off-task for an enrolled student, cutting against the **≥75% completion** key metric on the page where completion is earned. Without rails the column leaves dead space, the original reason to drop.

**Consequences:** Entity pages diverge from listing pages by design, recorded as a decision.
