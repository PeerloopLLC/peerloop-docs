## 1. Rails-backed lanes in the right rail — the executable cut of `[RECO-UNIFY]` #34
**Type:** Strategic
**Topics:** architecture, ui, discovery

**Trigger:** `[REC-REHOME]` gated MERGE-BRIAN §2 M4 and §3 N8; both were dispositioned "ADAPT — hide only after rehoming", so a destination had to be chosen before either could be built.

**Options Considered:**
1. Move the carousels as-is into the right rail — cheapest, but keeps the duplicate recommender `[RECO-UNIFY]` exists to remove
2. Rails-backed lanes in the right rail ← **Chosen** — rebuild as vertical lanes off the Discovery Rails blob; delete `/api/recommendations/*`
3. Retire into SmartFeed entirely — delete both components and both APIs; Home's suggestion-cards already do the job
4. Full `[RECO-UNIFY]` #34 including Peerloop Picks + Promoted lanes — needs `[PROMOTE-PIPELINE]` Steps 4–7, so multi-conv

**Decision:** Option 2 — For You · Trending · New · Popular lanes in the existing right-hand `<aside>` on `/courses`, `/communities` and `/`, backed by the single global Discovery Rails blob; both `/api/recommendations/*` endpoints deleted.

**Rationale:** Retires the duplicate recommender that `[RECO-UNIFY]` was written to remove; uses machinery already shipped (`lib/discovery-rails/client.ts`, Conv 261, tests-only until now); fills a designed empty slot; unblocks both gated mechanisms in one move. Defers only the Promotion lanes, which are genuinely gated on other work.

**Consequences:** `RecommendedCourses`/`RecommendedCommunities` and both endpoints deleted (−44 tests). New `DiscoveryRails` + `DiscoveryRailCard` + `lib/discovery-rails/lanes.ts` (+20 tests). §3 complete; §2 down to M3. `[RECO-UNIFY]` #34 half-shipped. Accepted caveat: the rail is `hidden lg:block`, so no recommendations surface below `lg`.

## 2. A separate rail card, not a fourth `CourseCatalogCard` variant
**Type:** Implementation
**Topics:** components, architecture

**Trigger:** §2 M9 and §3 N11 both added *named variants* to the catalog cards, so variant-addition was the established pattern to follow here.

**Options Considered:**
1. Add `variant="rail"` to `CourseCatalogCard` + `CommunityCatalogCard` — follows the recent precedent
2. One new compact card serving both entity types ← **Chosen**

**Decision:** A separate `DiscoveryRailCard`.

**Rationale:** `RailEntity` carries no price, rating, level or creator. A `rail` variant would mean making four currently-required props optional and threading an "absent" state through three existing variants — the exact stranding pattern `CourseCatalogCard`'s own header documents from Conv 425, when the `context` prop's branches went unreachable while tsc, lint and the whole suite stayed green (`[ORPHAN-DETECT]`). The rails payload is uniform across entity types, so one card serves both honestly.

**Consequences:** Both catalog cards untouched except doc comments. Surfaced that `variant="overlay"` now has **zero** production call sites on both cards (the carousels were its only hosts) → new `[OVERLAY-ORPHAN]` task rather than a unilateral deletion.

## 3. Drop the per-carousel dismiss control
**Type:** Implementation
**Topics:** ui, product

**Trigger:** Both carousels carried a localStorage dismiss; the rail replaces them.

**Options Considered:**
1. Preserve a whole-rail dismiss
2. Drop it, flag the drop ← **Chosen**

**Decision:** No dismiss on the rail.

**Rationale:** The rail occupies space that was an empty placeholder, so there is nothing for it to be in the way of; and the dismiss that actually *trains* recommendations is the feed's (`/api/feeds/smart/dismiss`), which is unaffected. Per `feedback_port_functionality_and_styling` a port must not silently lose behaviour — so it was stated as a deliberate drop rather than quietly omitted.

**Consequences:** Documented in the component header, the build log and the user-facing summary. Reversible on request.

## 4. `[OVERLAY-ORPHAN]` logged rather than acted on
**Type:** Implementation
**Topics:** dead-code, process

**Trigger:** After deleting the carousels, `git grep 'variant="overlay"' -- src/` returned zero hits on both catalog cards.

**Options Considered:**
1. Delete the variant now — Conv 425's precedent in that same file removed a stranded path rather than let it rot
2. Log it as a keep-or-delete task, NOTE both files ← **Chosen**

**Decision:** Task `[OVERLAY-ORPHAN]`, plus a pointer NOTE in both component headers.

**Rationale:** The Conv-425 precedent removed `context`, whose branches were unreachable **and** undocumented. `overlay` is different: coherent, named, tested, and the obvious answer for a future image-backdrop band. The user's chosen scope was the rehome; deleting two variants and their tests is adjacent work whose blast radius they should size.

**Consequences:** Nothing rots silently — both files point at the task.

## 5. Delete `API-RECOMMENDATIONS.md` rather than rewrite it
**Type:** Implementation
**Topics:** docs, docs-infra

**Trigger:** A 144-line `driftCheck` doc describing two endpoints that no longer exist.

**Options Considered:**

**Consequences:** Doc set has no dangling endpoint references. Test-doc totals re-verified against on-disk reality (240/82/34/28 → vitest 400, all 428) rather than carried from the changelog.
