## 1. MF-SKEW resolution — exact-pin wrangler 4.112.0 + workers-types v5 (dedupe over caret / override / .npmrc flag)
**Type:** Implementation
**Topics:** cloudflare, deployment, dev-tooling

**Trigger:** Conv-415 left [MF-SKEW] as next-conv #1 ("cannot have the dev tooling this brittle") — two miniflare copies (wrangler 4.94→4.20260521 vs `@cloudflare/vite-plugin` 1.45.1→4.20260714) crashing the older CLI on the newer `_cf_ALARM` schema. The Conv-415 "sweet spot" (mf ≥714 + workers-types v4 peer) was found NOT to exist: the wt peer flips ^4→^5 at wrangler 4.108 (mf 20260706), before mf reaches 714 at 4.112.

**Options Considered:**
- Pin mechanism: caret `^4.112.0` (a fresh install floats wrangler to a version with a *different* mf pin → re-split → crash returns) / **exact `4.112.0`** ← Chosen (both wrangler and vite-plugin then pin 4.20260714.0 → npm collapses to ONE shared copy) / npm `override` (rejected in Conv 415 — fragile given miniflare↔workerd coupling).
- workers-types conflict: **bump to v5 (5.20260724.1)** ← Chosen (measured: v4 baseline 0 tsc errors → v5 install clean, tsc still 0 errors — the Conv-415 "codebase-wide fallout" fear was unfounded) / committed `.npmrc legacy-peer-deps=true` (rejected — broad, brittle, silences all peer checks).
- Global: **bump global nvm wrangler 4.58→4.112** ← Chosen (the global shadows the project's `node_modules` on PATH, so alignment must fix both).

**Decision:** Exact-pin `wrangler@4.112.0`, bump `@cloudflare/workers-types`→v5, bump the global nvm wrangler to 4.112.0. Also removed the dead `r2:list:*` scripts (`r2 object list` is not a valid wrangler subcommand) and refreshed the seed-r2-dev.mjs skew comment.

**Rationale:** An exact pin that matches the vite-plugin's pin is the only mechanism that makes the skew *structurally* impossible (one shared copy) rather than merely currently-aligned; a caret re-opens the gap on the next float. The v5 bump was the measured-clean unblock for the ERESOLVE conflict, strictly better than globally disabling peer checks.

**Consequences:** miniflare deduped to ONE copy 4.20260714.0; live-verified `wrangler d1 execute --local` + `db:seed:r2:local` (7/7 blobs) run cleanly (previously the exact crash). All 5 gates green (suite 6552). Committed `3de05f0f`. Memory `project_wrangler_exact_pin_miniflare_dedupe` written. Supersedes the Conv-415 "deferred" MF-SKEW decision (08-deployment-infra.md).

## 2. Course "Write a Review" affordance — Modal + full composer now, gated on the exact API predicate
**Type:** Implementation
**Topics:** astro, testing, ui

**Trigger:** On `/course/[slug]` the "Write a Review" element looked like a button but wasn't clickable. User: "We have a review UI after a session ends… inspect that for ideas. And also check if there are criteria for whether or not to display the button. There should be."

**Options Considered:**
- Surface: **Modal dialog** ← Chosen / inline composer.
- Scope: **full composer + gating now** ← Chosen / stub-then-defer.
- Gating source: the existing `courseComplete` **journey proxy** (isComplete OR all-modules-done — can diverge from real status → a button whose POST 400s) / the **real `enrollment.status === 'completed'` + no-existing-review**, exactly what `POST /course-review` enforces ← Chosen (computed via a LEFT JOIN in `[...tab].astro`).

**Decision:** Built `CourseReviewComposer` (Modal + StarRating + Textarea + collapsible clarity/relevance/depth sub-ratings), modelled on `SessionCompletedView` (the post-session rating UI). Three states: write / already-reviewed read-only ("You reviewed this ★N") / hidden — driven by the real enrollment status.

**Rationale:** Reuse the proven post-session rating template. Gating display on the same predicate the endpoint accepts guarantees display and acceptance always agree (no button that then 400s). Establishes the **API-aligned gating** convention.

**Consequences:** Verified end-to-end vs seed (David in_progress→hidden; flipped→completed→write state; POST 200; →read-only; reverted DB + fixed aggregate drift). All 5 gates green (6552). Committed `d450ae2c`.

## 4. Messages `?to=` deep-link — exact by-id resolve branch + run-once guard (not a new messageability gate)
**Type:** Implementation
**Topics:** ui, testing

**Trigger:** "Ask a Question" (the first feature to message someone with no existing thread) surfaced 3 symptoms on the shared messages page: destination user not preloaded / no name; modal stuck on the Messages page; modal reappears ~3s after every dismiss (endless).

**Options Considered:**
- Preselect resolve: keep `/api/users/search?q={id}` (name/handle match only → raw id returns `[]`) / add an **exact by-id branch `?id=`** ← Chosen.
- Reopen loop: leave the `?to=` effect firing on every 10s poll (`conversations` dep, no guard, param never cleared) / **run-once ref guard + strip the `?to=` URL param + clear intent on modal close** ← Chosen.
- Messageability: treat as a blocker needing a new gate / **not a blocker** ← Chosen (messageability is open per Conv 110; the `?to=` links are the correct documented deep-link).

**Decision:** Added an exact by-id branch to `/api/users/search`; NewConversationModal preselect uses `?id=`; MessagesCenter gets a run-once ref guard, strips the `?to=` URL param, and clears intent on close.

**Rationale:** The deep-link contract is correct; the two bugs are pre-existing in the shared page (search can't resolve a raw id; the effect had no run-once guard). Fix them at the source rather than adding a special-case gate.

**Consequences:** Verified e2e via Playwright + screenshot (client-user cache warmup): modal opens with "Guy Rymberg @guy-rymberg" preloaded, closes and stays closed, no reappear after 12s (> one poll cycle). All 5 gates green (6552). Committed `d450ae2c`.
