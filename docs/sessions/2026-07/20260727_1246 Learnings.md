# Conv Learnings - 2026-07-27

## 1. React 19 removed `_debugSource`, but `_debugStack` still yields the call site
**Topics:** react, testing, tooling

**Context:** Needed to attribute a rendered DOM icon back to the source line that wrote its size class, to convert page-level coverage into per-element coverage.

**Learning:** React 19 dev fibers expose `_debugInfo`, `_debugOwner`, `_debugStack`, `_debugTask`, `_debugNeedsRemount`, `_debugHookTypes` — but **not** `_debugSource` (removed in 19). `_debugStack` is an Error carrying the JSX creation stack, whose first non-React frame is the creating component. The `<svg>`'s own stack points at the icon component's internals; the fiber one level up (the `<MattIcon>` element) points at the caller. Walking up while `className` is the same string reliably lands on the call site — 95% attribution (252 of 265 over 6 routes) with zero production changes.

**Pattern:**
```js
const fiber = el[Object.keys(el).find(k => k.startsWith('__reactFiber$'))];
const cn = fiber.memoizedProps?.className;
let best = fiber, up = fiber.return;
for (let h = 0; up && h < 8; h++) {
  if (cn !== undefined && up.memoizedProps?.className === cn) best = up;
  else if (up.memoizedProps?.className !== undefined) break;
  up = up.return;
}
// best._debugStack → first non-node_modules frame = the call site
```

## 2. Closed prop interfaces make build-time instrumentation impossible
**Topics:** react, tooling, architecture

**Context:** The planned attribution design was a dev-only babel/Vite transform stamping `data-icon-src` at each call site.

**Learning:** The stamp only reaches the DOM if the receiving component forwards unknown props. `MattIcon` (`{name, className}`) and all 98 `ui/icons.tsx` components (`{className}`) have **closed interfaces with no `...rest`**, so an injected attribute is silently dropped — no error, just absent output. Checking the target components' prop signatures *before* building the transform is what turned a multi-hour build into a 10-minute spike. A dev-only measurement is never worth changing shared production primitives to enable.

## 3. Vite dev stack traces carry transformed-module line numbers, not source lines
**Topics:** vite, tooling, testing

**Context:** The attribution stack produced frames like `IconLabelChip.tsx:43:30`.

**Learning:** `error.stack` is **not** source-mapped (devtools applies maps for display only), so the line refers to the *served, transformed* module. Verified: source line 43 of `IconLabelChip.tsx` is an interface declaration, not JSX. These numbers are therefore valid as **stable per-site identities** (distinct sites → distinct numbers; a site rendered in a loop keeps one) but must never be reported as source pointers. The ledger aggregates per file for exactly this reason.

## 4. "Zero rows" is not "renders the empty state" — the route guard decides
**Topics:** testing, seed-data

**Context:** Needed a user that would render empty-list states across `/learning`, `/teaching`, `/creating`.

**Learning:** The obvious pick (`fraser@meristics.com`: 0 enrollments, 0 notifications, 0 conversations) also has **0 capability flags**, so capability-guarded routes bounce it entirely rather than rendering an empty list. An empty-state driver must be data-empty **and** capability-bearing — here `usr-admin` (all three flags, zero data). Another face of the `[PREMISE]` pattern: verify against the consumer (the guard), not the data.

## 5. Astro-SSR'd icons have no React fiber — a permanent blind spot for fiber-based attribution
**Topics:** astro, react, tooling

**Context:** 151 rendered icons across the sweep produced no attribution.

**Learning:** Icons rendered by `.astro` components without a `client:*` directive are static HTML with no fiber, so fiber-walking cannot see them at all (61 static sites). This is a property of the technique, not a coverage gap — it must be reported as a named blind spot and excluded from the residue denominator, or it looks like unproven work forever.

## 6. Component defaults can be near-dead by construction
**Topics:** react, design-system

**Context:** The ledger showed `ui/icons.tsx` at 99 of 99 sites unproven.

**Learning:** Measured before treating it as a coverage gap: the file exports 98 icon components each defaulting to `className = 'size-icon-20'`, but only **6 usages in the whole app omit `className`** (4 of those in the parked `BecomeATeacherPage`) against **381** that pass their own. The defaults exist but almost never render. Third independent measurement undercutting the Conv-420 "component defaults are the high-leverage target" claim, after the audit's "MattIcon's default fires on 23 of 199 call sites".

## 7. `\s*` vs `\s+` silently inverted a classifier's meaning
**Topics:** regex, tooling

**Context:** The ledger classified sites as "component default" vs "call site".

**Learning:** A destructuring default is `className = 'x'` (whitespace before `=`); a JSX attribute is `className="x"` (none). `className\s*=\s*` matches **both**, so 625 of 690 sites were mislabelled as defaults. The code comment stated the rule correctly while the regex contradicted it — comments do not constrain behaviour. Caught only because 27 "defaults" in `Sidebar.tsx` (a consumer) was implausible. Same class as the Conv-421 index-pairing false positive: **predict a number before trusting the instrument that produces it.**

## 8. A failing login should degrade, not abort a sweep
**Topics:** tooling, testing

**Context:** A guessed seed email (`marcus.thompson@` vs the real `marcus.t@`) threw inside the per-user login.

**Learning:** The throw propagated out of the group loop and killed the run at route 46 of 95, discarding every later group's measurements for one typo. Long multi-actor sweeps should isolate per-actor failures — skip the group, count its routes unreachable, keep going.
