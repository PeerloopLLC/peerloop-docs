# Conv Decisions - 2026-07-27

## 1. Attribute via React fiber `_debugStack` rather than a build-time stamp
**Type:** Implementation
**Topics:** tooling, react, testing

**Trigger:** Phase 5 closed with a named residue: coverage was per-page, so "every rendered token scaled" could not answer "which source sites never rendered".

**Options Considered:**
1. Dev-only babel/Vite transform stamping `data-icon-src="file:line"` at each call site — the originally proposed and user-approved design
2. React 19 fiber `_debugStack` walk at measurement time ← Chosen
3. Modify `MattIcon` + `ui/icons.tsx` to spread `...rest` so a stamp could reach the DOM

**Decision:** Use the fiber `_debugStack` walk; abandon the transform.

**Rationale:** The spike found the transform unworkable — the icon primitives have closed prop interfaces, so an injected attribute is dropped. Option 3 would change shared production components purely to serve a dev-only measurement, which is a bad trade. Option 2 needs no build tooling, no production change, and carries no prod-build risk, and measured 95% attribution.

**Consequences:** No new build-time tooling entered the stack. Two limits are inherent and now encoded in the tool: transformed-module line numbers (so the ledger aggregates per file) and `.astro` icons having no fiber (reported as a named blind spot).

> **Insight:** A measurement instrument that requires changing the thing being measured has already failed its own design review — the cheapest way to find out is to read the target's prop signature before writing the transform, not after.

## 2. Fix the 4 mis-tokened non-icons rather than baselining them
**Type:** Implementation
**Topics:** design-system, icon-sizing

**Trigger:** The widened sweep raised `tokened-did-not-scale: 0 → 4`, traced to Conv 420's tranche 2 (`c429f150`).

**Options Considered:**
1. Fix the 4 and regenerate the baseline ← Chosen
2. Fix the 4 only, leaving the baseline describing 26 routes
3. Accept them as known findings and bake them into the new baseline

**Decision:** Fix, then regenerate.

**Rationale:** Not cosmetic — the token sized height while the adjacent `w-[Npx]` held width, so a thumbnail distorts 56×40 → 56×60 at a 24px root. Each was also a permanent false positive in the block's own completeness instrument; baselining them would have poisoned the measurement permanently.

**Consequences:** 4 sites reverted to arbitrary px (`h-[40px]`/`h-[24px]`/`h-[32px]`), pixel-identical at the default root. Both static counters unchanged (25 governed / 532 informational), confirming the edits landed in neither bucket. Baseline now describes 97 route-states.

## 3. Ledger reports per-file, and excludes `.astro` from the residue
**Type:** Implementation
**Topics:** tooling, testing

**Trigger:** Stack line numbers proved to be transformed-module lines, and `.astro` icons produced no attribution at all.

**Options Considered:**
1. Report `file:line` as source pointers
2. Aggregate per file; exclude `.astro` sites into a named blind-spot line ← Chosen
3. Add sourcemap resolution to recover true source lines

**Decision:** Aggregate per file; name the `.astro` blind spot explicitly rather than counting it as residue.

**Rationale:** Reporting an unverified source line would send a reader to the wrong place. Option 3 adds real complexity for precision the completeness question doesn't need. Leaving `.astro` in the residue would make 61 sites look permanently unproven when they are simply outside the technique.

**Consequences:** The ledger's headline is trustworthy at file granularity; the blind spot is visible rather than silently folded into a percentage.
