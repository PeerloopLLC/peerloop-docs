## 4. Promote the icon guard to an absolute gate, not baseline-relative
**Type:** Implementation
**Topics:** ci, icon-sizing

**Trigger:** Phase 6 warn→error, with the baseline now at zero.

**Options Considered:**
1. Keep baseline-relative (fires only on per-file increases)
2. Absolute — any governed violation fails ← Chosen

**Decision:** Absolute, plus `--update-baseline` refuses to write a non-zero governed baseline, plus wired into `npm run verify`.

**Rationale:** The baseline-relative design existed because a hard gate would have been red on day one at 1,863 violations; that rationale is spent. An open re-snapshot path would have preserved the escape hatch the promotion removes.

**Consequences:** Verified by injection — clean → exit 0, violation → exit 1, launder attempt → exit 1, chain fails fast.

## 6. Keep the 98 `ui/icons.tsx` size defaults, but exclude them from the ledger denominator
**Type:** Implementation
**Topics:** icon-sizing, metrics

**Trigger:** Open question: are the near-dead defaults worth keeping?

**Options Considered:**
1. Keep, exclude from denominator ← Chosen
2. Remove — make `className` required in `IconProps`
3. Keep exactly as-is

**Decision:** Keep as the fallback for future call sites; `reportLedger()` excludes them from the denominator and reports them separately.

**Rationale:** 0 of 395 resolved usages rely on a default, so a default can never be *proven* by rendering — counting them as unproven residue overstated the gap permanently. They remain the thing that makes a future `<FeedIcon />` render at 20px rather than unsized.

**Consequences:** Denominator 635 → 528 attributable call sites.
