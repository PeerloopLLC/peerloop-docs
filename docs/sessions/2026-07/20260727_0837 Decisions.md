# Conv Decisions - 2026-07-27

## 1. Rescind the em inline-icon family — the icon rule collapses to two-way
**Type:** Strategic
**Topics:** design-system, design-tokens

**Trigger:** User asked "what do you think about rescinding all em usage?" — the block's longest-open decision, dodged three times.

**Options Considered:**
1. Keep em (leaves ~500 remaining sites each needing an inline-vs-standalone judgment)
2. Rescind but keep the tokens defined for a future case
3. **Rescind entirely — delete tokens, convert call sites, collapse the rule ← Chosen**

**Decision:** `--icon-inline-{sm,md,lg}` deleted from `tokens-primitives.css` and the `--spacing-*` bridge; all 6 call sites → `size-icon-16`. Icons are **rem only**; arbitrary px remains for genuine non-icons. This supersedes the Conv-419 three-way split on its inline arm.

**Rationale:** Four findings unavailable in Conv 419. (1) It never fired — three dodges. (2) Two thirds was dead: `-sm`/`-lg` had zero usages ever. (3) The promise was not delivered — `em` resolves against the container's font-size, not the sibling label's. (4) The 14px anchor capped at 17.4px against this app's recurring 12px labels.

**Consequences:** The ~500 remaining sites became mechanical rather than judgment calls, which is what made the same-conv sweep possible. Verification then showed the rescind was a **repair**: the em token had been rendering 6 of 7 `PromoteButton` icons at 13.8px (−14%) since Conv 420. The scanner's dead `inline-did-not-scale` rule was strengthened to `tokened-did-not-scale`, widening the completeness proof from the inline arm to the whole axis.

> **Insight:** A design token whose every applicable case was resolved by classifying *around* it is not an underused token — it is an unmade decision wearing the costume of a rule. Counting the dodges, rather than re-arguing each case, is what converts it back into a decision.

**Routed to:** `docs/decisions/05-ui-ux-components.md` + `decision-log.md` + `INDEX.md` (in-conv, commits `82f67e5` / `c91288e`).

## 2. Split the icon axis out of the dimension count so the baseline measures progress
**Type:** Implementation
**Topics:** tooling, design-system, testing

**Trigger:** The `[ICON-AUDIT]` finding that the guard's headline number conflated migration, deletion and rule-narrowing.

**Options Considered:**
1. A only — regex precision fixes (~45 min)
2. Skip the split, just migrate and let the count fall
3. Write the scope up and decide later
4. **A+B+C — precision + classification + calibration ← Chosen**

**Decision:** R1 classifies structurally into `icon-bare-numeric-{overridden,multiplier}` (gated) vs `dimension-bare-numeric` (measured, reported, **not** gated). Only governed rules count toward the headline total and drive regression.

**Rationale:** Scoping by measurement found **three** inflation sources, not the assumed one — 51 fraction false positives, 94 `min-`/`max-` mislabels, ~418 non-icon elements. A alone leaves the classification problem; B without A means classifying 145 phantom violations.

**Consequences:** Baseline 1,143 → 560 governed + 532 informational. Icon context is decided by testing match offsets against whole-**tag** ranges *and* icon **definition-body** ranges — line proximity was tried and rejected for misreading sentinel divs. Calibrated per `[CMH]` before commit with 14 regex cases and a 6-shape injected probe.

> **Insight:** A gate's headline number is a product claim, and a claim that mixes migration, deletion and rule-narrowing cannot be falsified by anyone reading it. Splitting a metric into *governed* and *informational* tiers keeps the unowned data visible without letting it inflate — or deflate — the progress it does not measure.

**Routed to:** `docs/decisions/06-testing-ci.md` + `decision-log.md` + `INDEX.md`.

## 3. Repair the whole legacy shell header rather than the tasked one-line avatar fix
**Type:** Implementation
**Topics:** design-system, tailwind

**Trigger:** `[HDR-AVATAR]` described a one-line change; measurement showed it was not isolatable.

**Options Considered:**
1. Fix only the avatar as tasked (puts a 32px avatar in a 17px bar — overflows)
2. Defer, since it's the legacy shell
3. **Repair the component whole, per the `ModeratorInvite` precedent ← Chosen**

**Decision:** 15 classes converted to the literal-px convention, preserving v3 author intent.

**Rationale:** The bar is `h-16` meaning 64px and **rendering 17px**, with 28px logo text overflowing it. The tranche-3a precedent (Conv 420, user-authorised) covers exactly this: a legacy-semantics component where the icon axis alone cannot fix a visible defect. Blast radius is **7 live non-`/old` routes**, not legacy-only — including `/receipt/[id]`, a Conv-410 deliverable, and `/invite/mod/[token]`, whose content Conv 420 repaired while leaving this shell broken.

**Consequences:** Header 17px → 65px, avatar 8px → 32px. The task's own scope was wrong twice over — `h-8 w-8` appears on both the `<img>` and the initials fallback.

> **Insight:** "Legacy shell" is a claim about intent, not about reach. Before scoping a repair by the label a component carries, enumerate the routes that actually mount it — the second component in a row here turned out to render on live, client-facing surfaces.

**Routed to:** `docs/decisions/05-ui-ux-components.md` + `decision-log.md` + `INDEX.md`.
