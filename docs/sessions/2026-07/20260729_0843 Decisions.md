# Conv Decisions - 2026-07-29

## 1. The workspace data model is the existing principle, scoped — not a new rule
**Type:** Strategic
**Topics:** astro, d1, docs-infra

**Trigger:** `[WS-DATA-MODEL]` asked which of three sourcing models the three role workspaces should adopt.

**Options Considered:**
1. CurrentUser-first everywhere — **not implementable**; the endpoints carry other users' rows and money
2. API-first everywhere — build `/api/me/student-dashboard`; re-serves enrollment data CurrentUser already renders correctly
3. Codify the existing boundary ← **Chosen**
4. Fix the defects only, leave the model undecided

**Decision:** Adopt (3), which turned out to mean *scoping* the already-documented "Principle: Consume What's Loaded" (Conv 014) rather than writing anything new. The principle governs **whole-endpoint redundancy and wrong-source reads**, NOT trimming individually-derivable fields out of endpoints that must exist anyway.

**Rationale:** The boundary is a **freshness contract**, not a stylistic preference: CurrentUser is cached + 30s-polled, which is the tolerance of identity and own-course relationships and not of money, queues, or other people's state. That also reframes Conv 428's `TeacherCertifications` change as the principle being *followed*, not the drift it was logged as.

**Consequences:** `teaching_courses[]` and `students_helped_total` stay on their endpoints (that would have been option B, declined). One redundancy found across all 18 `/api/me/*`: `/api/me/diplomas` retired. `/api/me/certificates` checked and kept.

> **Insight:** A cache-freshness window is a data-classification tool, not just a performance knob — once "what tolerates 30s of staleness?" is the question, the sourcing boundary falls out of the domain rather than out of taste.

## 2. Retire `/api/me/diplomas`; keep `/api/me/certificates`
**Type:** Implementation
**Topics:** d1, astro

**Trigger:** The audit's single whole-endpoint redundancy hit.

**Decision:** Delete `/api/me/diplomas` + its test; `DiplomasSection` reads `useCurrentUser().getDiplomas()`. Keep `/api/me/certificates`.

**Rationale:** A Diploma has no table — it *is* the completed enrollment, so the endpoint re-selected rows CurrentUser had already loaded, needing only 2 more columns from a row `/api/me/full` already reads. `certificates` is a genuinely separate table (schema `:679`) from `teacher_certifications` (`:658`), with its own id/type/status/issued_at/certificate_url.

**Consequences:** `UserEnrollment` gained `enrollmentId` + `diplomaAwardedAt`; `/learning` drops from 4 requests to 3. Made the `data_version` fix a hard prerequisite — otherwise diplomas would have moved from fetch-fresh into the stale set.

## 3. Follow the cache guard's own prior decision rather than extend it
**Type:** Implementation
**Topics:** astro, cc-workflow

**Trigger:** Pre-Conv-430 cached enrollments lack `enrollmentId`, which would render `/diploma/undefined`.

**Options Considered:**
1. Add an array-element check to `isValidCachedData`
2. Bump a cache version key
3. Tolerate in the getter ← **Chosen**

**Decision:** Filter rows with no `enrollmentId` inside `getDiplomas()`.

**Rationale:** `state-management.md:428-430` explicitly lists "array element shapes" as deliberately NOT checked ("corrected by the API refresh"), and :447 rejects full schema validation as a maintenance burden. Options 1 and 2 both contradict recorded decisions. Option 3 matches the existing `timezone ?? null` tolerance pattern.

**Consequences:** Self-heals on the ~200ms refresh; no guard maintenance burden added.

## 4. Make the Extract prune a script, not an instruction
**Type:** Strategic
**Topics:** cc-workflow, docs-infra

**Trigger:** `[PRUNESAFE]` — Conv 429's prune honoured a 140-line self-reported manifest and cut §Completed 8 items → 1.

**Options Considered:**
1. Strengthen the agent's manifest instruction
2. Prose instructions in Step 4b describing the intersection
3. Deterministic script computing spans from the file ← **Chosen**

**Decision:** `.claude/scripts/extract-prune.mjs` + `extract-prune.test.sh`; Step 4b becomes "run the script".

**Rationale:** Options 1 and 2 both leave agent judgment in the loop — the exact mechanism that failed. Computing spans from the Extract's own headings makes every other section unreachable by construction. Follows the established `.mjs` + `.test.sh` convention already in `.claude/scripts/`.

**Consequences:** Exit codes 0/2/3 with a >50% refusal belt; the agent instruction kept but annotated. First exercised by this conv's own `/r-end`.

> **Insight:** When a guard and the failure it was meant to catch run on the same faculty, hardening the guard is a no-op — the fix has to move the check to a different substrate.
