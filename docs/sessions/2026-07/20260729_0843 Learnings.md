# Conv Learnings - 2026-07-29

## 1. Ask whether the rule already exists before writing one
**Topics:** cc-workflow, docs-infra

**Context:** `[WS-DATA-MODEL]` was logged across two convs as "the model has never been decided". I repeated that framing, then found `state-management.md:288` — "Principle: Consume What's Loaded", decided Conv 014, with the freshness split already stated at :281.

**Learning:** A task's own description is a hypothesis about the codebase, not a fact — and that extends to claims about what has *not* been decided. The doc tree had answered a question two convs deferred. Reading the doc first would have saved the whole first pass.

**Pattern:** Before designing a convention, grep the `docs/as-designed/` tree for the concept. If a doc section exists, the work is usually *scoping or enforcing* it, not authoring it.

## 2. A task premise can be falsifiable in the option set itself
**Topics:** cc-workflow

**Context:** `[WS-DATA-MODEL]` offered three options; option (a) was "CurrentUser-first everywhere — `/teaching` and `/creating` shed aggregate endpoints".

**Learning:** Reading the endpoints showed (a) is not implementable at all — they are mostly other users' rows and money, which CurrentUser structurally cannot carry. The right move was to say so before the pick, not to let the user choose between one real option and two impossible ones.

**Pattern:** When presenting a decision, verify each option is *achievable* before offering it. An option list is a claim about the world too.

## 3. The named axis is not always the axis that varies
**Topics:** cc-workflow

**Context:** The task framed the inconsistency as "CurrentUser-first vs API-first".

**Learning:** On the sourcing axis all three workspaces were already consistent (identity/relationships from CurrentUser, everything else from endpoints). What actually varied was *round-trip count* — `/learning` 4, `/teaching` 3, `/creating` 2 — and the CurrentUser-first workspace made the most, inverting the intuition behind the proposed fix.

**Pattern:** Measure the thing before accepting the frame. A count per surface is cheap and often reframes the question.

## 4. A shared mutation helper must own its side-effects
**Topics:** d1, cc-workflow

**Context:** `[CMPL-NOBUMP]` — `onEnrollmentCompleted` has three callers; the two API endpoints bumped `data_version`, `lib/booking.ts` didn't, and that's the BBB-webhook/cron path.

**Learning:** Putting a side-effect in the callers means it is correct only for as many callers as someone remembered. The doc even asserted "enrollment CRUD bumps data_version" — true for 2 of 3. Moving the bump into the helper made it true by construction.

**Pattern:** When auditing a "does X always happen?" claim, enumerate the call sites and check each. The count of paths that do it is the real answer, not the doc's summary.

## 5. Structural prevention beats a sterner instruction
**Topics:** cc-workflow, docs-infra

**Context:** `[PRUNESAFE]` — Step 4b deleted every line an agent's self-reported manifest listed, guarded only by "only record lines you actually copied".

**Learning:** The safeguard and the failure were the same mechanism: agent judgment about its own behaviour. Rewriting the instruction more firmly would have been that mechanism a second time. Computing the eligible spans from the file's own structure removes the judgment from the loop entirely.

**Pattern:** Same shape as Conv 273 (AskUserQuestion replacing the QLINT Stop-hook). When a guard has failed once, ask whether it is *detecting* misbehaviour or *preventing* it.

## 6. Calibrate in both directions or the fixture may pass vacuously
**Topics:** testing

**Context:** The `extract-prune` fixture asserts the filtered prune leaves §Prompts/§Completed/§Open Questions intact.

**Learning:** That assertion alone would also pass against a pruner that deletes nothing at all. Adding the reverse — the *unfiltered* prune on the same manifest still destroys those sections — is what proves the fixture actually exercises the bug.

**Pattern:** For any "the fix prevents X" test, add a companion showing X still happens without the fix.

---

## 7. A test label that doesn't match its measurement is a false-confidence bug
**Topics:** testing

**Context:** Wrote `check "§Completed still has 8 items" "$(grep -c '^- \[' ...)" "4"` — the label said 8, the assertion measured 4 (only bracketed task codes matched).

**Learning:** It passed, and it was measuring the wrong thing. In a suite written to prevent content loss, an assertion whose name misdescribes it is the same failure class one level up.

**Pattern:** Read each assertion's label against its expression once before committing a new test file.

---

## 8. Partial duck-type mocks rot when the real class grows
**Topics:** testing

**Context:** Adding `getDiplomas()` to `CurrentUser` broke 23 tests in `StudentDashboard.test.tsx`, which mocks the class as a hand-rolled object with 4 methods.

**Learning:** The mock silently encodes "these are the only methods anyone calls" — true when written, false forever after. `DiplomasSection.test.tsx` constructs a real `CurrentUser` from a `MeFullResponse` fixture instead, which cannot drift this way.

**Pattern:** For a class with an evolving surface, build the real instance from its own input type rather than duck-typing the methods a component happens to use today.

---

## 9. State plainly when a specified calibration is impossible
**Topics:** cc-workflow, testing

**Context:** `[PRUNESAFE]` specified replaying Conv 429's manifest against its pre-prune Extract. Step 4b `rm`s the manifest and the Extract was only committed post-prune, so neither exists.

**Learning:** The options were to quietly substitute a fixture and call it "calibrated", or to say the replay is impossible and record what was actually done. The second is the only one that leaves an honest record for whoever reads the test in six months.

**Pattern:** When a task's verification method turns out to be unavailable, say so in the artefact itself (test header / commit body), not just in chat.
