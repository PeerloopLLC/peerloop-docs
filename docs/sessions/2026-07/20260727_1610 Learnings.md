# Conv Learnings - 2026-07-27

## 1. A memo whose two claims cannot both be true is a re-measure signal, not a reference
**Topics:** debugging, memory-discipline, tooling

**Context:** `[BRIDGE-DIAG]`. The Conv-413 memo claimed `curl` returned 200 on **both** loopback literals while also stating the server binds `[::1]` only.

**Learning:** Those cannot hold simultaneously — the contradiction sat in plain text for four convs. What made it invisible was that the *workaround worked*, so nothing ever forced a re-read. Observations taken under different configurations had been written up as if simultaneous.

**Pattern:** When recording a diagnosis, state the configuration each measurement was taken under. When reading one, check its claims against each other before trusting either.

---

## 2. Success-shaped tool results hide failures — confirm navigation by reading state back
**Topics:** browser-automation, tooling

**Context:** `navigate` returned `"Navigated to http://127.0.0.1:4321/"` while the tab actually sat on `chrome-error://chromewebdata/`.

**Learning:** The failure is invisible unless you read the page afterwards, so every retry looks like a success and the *browser* looks dead rather than the URL being wrong. The same class appeared twice more this conv: `resize_window` reports `"Successfully resized … to 1600x1000"` while width never changes, and `--update-baseline` would happily snapshot violations away.

**Pattern:** After any state-changing browser call, read the state back (`location.href`, `innerWidth`). A `chrome-error://` URL is the tell.

## 3. Bound a "window to the next match" — the last window swallows the file
**Topics:** static-analysis, tooling

**Context:** `iconRanges()` in `check-icon-sizing.ts` built `[def.start, nextDef.start ?? text.length]` per icon definition.

**Learning:** The final window extended to EOF, so every `<div className="w-12 h-12">` after the last icon definition was governed as an icon — 13 of 25 reported violations. The function's own doc-comment explicitly rejects line-proximity heuristics; this reintroduced one at file scale, and would have been enshrined by the warn→error promotion.

**Pattern:** Any `[start, nextMatch ?? end]` windowing needs a second bound (next top-level statement, brace balance, line budget). Verify the fix didn't over-correct by injecting a case that *must* still be caught.

## 4. Design a completeness check whose survivors are self-identifying
**Topics:** verification, refactoring

**Context:** Proving the Conv-423 449-site sweep missed nothing.

**Learning:** Every overridden number and every `N→N×4` rewrite output is a multiple of 4, so any surviving non-multiple-of-4 spacing utility is necessarily a missed site. That turned "did we miss anything?" into a finite, checkable set — and it resolved exactly: 92 survivors ↔ 92 pre-sweep fractional utilities, 1:1, zero mismatches. Stronger than route-by-route inspection because it covers routes never loaded.

**Pattern:** Look for an invariant the transform preserves that the *unfixed* cases violate; enumerate violators rather than sampling.

## 5. Grep on a bare tag name cannot distinguish a local wrapper from an imported export
**Topics:** static-analysis, premise-verification

**Context:** The plan recorded "6 usages omit className, 4 of them in `BecomeATeacherPage`" for the `ui/icons.tsx` defaults question.

**Learning:** All six were **name collisions** — `PromoteButton` and `BecomeATeacherPage` define their own local `CheckIcon`/`CloseIcon`, and `SocialPost` imports a different `entity/UserIcon`. Resolving each `from '@components/ui/icons'` import to its local (possibly aliased) name gives the true figure: **0 of 395**. Two wrong intermediate answers were produced before resolving imports.

**Pattern:** For "who consumes X?", resolve imports; never match the rendered tag name.

## 6. Predict the magnitude before trusting a new instrument
**Topics:** verification, tooling

**Context:** Three instruments produced wrong output before correction this conv.

**Learning:** (i) a non-multiple-of-4 detector matched `w-3/4` **fractions** as `w-3`; (ii) a delta-based pre/post comparison conflated originals-removed with survivors-added, so every row read MISMATCH until reframed as `after_integer == before_fractional`; (iii) `git grep` silently returns nothing for `\b`, reporting 0 where the working-tree grep found 172. Each was caught because a number looked implausible, not by re-reading code. This continues the pattern recorded in Convs 421–423.

**Pattern:** State the expected magnitude out loud before running a new measurement; a "0" or a "100% mismatch" is usually the instrument.

## 7. An error nothing runs is still a warning
**Topics:** ci, tooling

**Context:** Promoting `check:icons` warn → error.

**Learning:** The gate had never been part of `npm run verify`, so the promotion would have been nominal. Also closed the laundering path: `--update-baseline` now refuses to write a non-zero governed baseline, because a baseline-relative gate with an open re-snapshot escape hatch is not a gate.

**Pattern:** When promoting a check's severity, verify (a) something routinely runs it, and (b) there is no supported way to re-baseline the failure away.

---

## 8. Verify a fix is a fix before attributing blame to the recent change
**Topics:** debugging, regression-analysis

**Context:** The visual pass found three defects on pages the Conv-423 sweep touched.

**Learning:** All three were pre-existing, and each needed a different proof: `/admin/sessions` overflow (component byte-identical across the sweep, and its `gap-16 mb-24` are in the pre-existing override set); `line-height: 1` (present in `dc1f031e~1`, file last touched Conv 330); 8px icons (`w-8` = 8px before *and* after, since 8 is overridden). Proximity to a change is not causation.

**Pattern:** Before attributing a defect to a recent commit, check the file at `commit~1` and whether the values involved actually changed meaning.
