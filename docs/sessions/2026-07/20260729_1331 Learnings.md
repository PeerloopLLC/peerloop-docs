# Conv Learnings - 2026-07-29

## 1. A task's own description is a hypothesis — including its claims about what does *not* exist
**Topics:** process, task-management, cc-workflow

**Context:** `[REC-MOBILE]`'s body asserted that `DiscoveryRails` "renders lanes and nothing else (no panel chrome, no width)". The user's requirement set asked to "make the `/communities` aside use interests as well".

**Learning:** Three separate premises in this conv were false and each was caught only by reading the code. (a) The component **does** render panel chrome — `:146` is `rounded-16 border border-border-default bg-white p-16`; only the no-width half was true, and the component's own doc comment repeated the error. (b) The `/communities` aside **already** used interests — measured, 3 of 4 seeded communities resolve derived topics; the real gap was a cold-start hole, not an absence. (c) `feed_visits` looked like a ready-made recency store and was unusable for two independent reasons. This is the Conv-430 lesson recurring: verify the premise against the code before designing to it, and that includes claims about what has *not* been built.

**Pattern:** Before implementing a task, re-derive its factual claims from the source. Cheapest first: grep the definition, then read the consumers.

## 2. Coarse instrumentation reads as a defect
**Topics:** testing, browser-verification, process

**Context:** Three times this conv a live measurement appeared to show a broken feature and was actually the probe.

**Learning:** (a) No recency lane appeared after a visit — because For You had legitimately claimed that entity under the documented one-lane-per-entity rule. (b) A remove click appeared not to update — because `document.querySelector` returns the **first** DOM match and the narrow mount precedes the `<aside>`, so the hidden island's button was clicked. (c) The cross-island fix appeared to do nothing — because the probe measured lane *headings* while two entities were stored, so the lane correctly survived and only the row went. In each case a 🔴 alert was raised or nearly raised before investigating. A surprising live result is at least as likely to be the instrument as the product.

**Pattern:** Measure at the granularity of the thing that changed (rows, not headings). Scope DOM queries to the specific instance under test. Investigate before alerting.

## 3. The `storage` event cannot synchronise two components in the same document
**Topics:** browser-apis, react, astro

**Context:** Two `DiscoveryRails` islands per host held independent React state; a removal on one left the other stale.

**Learning:** The obvious fix — listen for `storage` — does not work. The spec fires `storage` **only in other documents**, never in the one that made the write. Same-document sync needs an in-document channel; `storage` covers only the cross-tab case. Both are needed for full coverage, and they are different mechanisms.

**Pattern:** In-document: a named `window` `CustomEvent` dispatched by the store's mutators (this codebase already does this — `courses:filterchange`, `communities:filterchange`, `lib/auth-modal.ts`'s `notifyChange`). Cross-tab: a `storage` listener filtered to the relevant keys.

## 4. Nothing in the five gates can detect a surface vanishing at a breakpoint
**Topics:** testing, ci, responsive

**Context:** Conv 427 removed the only personalized surface from every viewport under 1025px. All five gates were green then and stayed green.

**Learning:** A surface hidden behind a media query is not a type error, a lint error, a test failure or a build failure, and nothing in the suite asserts that a given surface renders at 375px. The regression survived only because the commit author wrote it down in prose and it was logged as a task. This is the same blind spot as `[MINWIDTH]` / `[SIDEBAR-COLLIDE]` — a third instance of the class.

**Pattern:** For any change that gates a surface behind a breakpoint, verify live at the narrow width; the gates will not.

## 5. Widening a type surfaces real distinctions rather than hiding them
**Topics:** typescript, testing

**Context:** Synthesizing recency entities into `RailEntity` needed `reason: 'recent'`, which `RailKind` did not allow.

**Learning:** Widening `RailEntity.reason` to `RailKind | 'recent'` immediately produced a compile error in an unrelated test helper that assigned `items[0].reason` to a blob rail's `kind`. That error was correct and useful: a *blob* rail genuinely cannot be `'recent'`, because `'recent'` only exists on client-synthesized entities. Narrowing the helper (rather than casting) preserved the distinction the type system had just pointed out.

**Pattern:** When a widened type breaks a call site, ask whether the break is telling you the two things really are different — and narrow at the call site rather than casting it away.

## 6. `mockResolvedValue` hands back the same `Response` every call
**Topics:** testing, vitest

**Context:** Two new de-dupe tests failed with "Body is unusable: Body has already been read".

**Learning:** `vi.fn().mockResolvedValue(jsonResponse(...))` evaluates the response **once** and returns that same object on every call; a `Response` body can only be read once. Existing tests never hit it because each fetched exactly once.

**Pattern:** Use `vi.fn(async () => jsonResponse(...))` when a test fetches more than once.

## 7. `define:vars` has zero uses in this codebase
**Topics:** astro, conventions

**Context:** Recording a visit needed page data on the client.

**Learning:** The obvious Astro approach — an inline `<script define:vars={...}>` — would have been a **new pattern** here (grep: zero occurrences), while every other client-side effect on those pages is already a `client:load` island. Chose a headless island.

**Pattern:** Check whether a "standard" framework feature is actually used in *this* repo before reaching for it.

---

## 8. `--spacing`-style project overrides mean stock framework values can't be assumed
**Topics:** tailwind, responsive

**Context:** Reasoning about who loses the aside below `lg`.

**Learning:** `lg` is **1025px** here, not Tailwind's stock 1024 (`tokens-tailwind-bridge.css:319`, Conv 175, Matt's desktop boundary). The one-pixel difference matters concretely: a 1024px-class landscape iPad falls *below* the cut.

**Pattern:** Always read the project's `@theme` block rather than assuming framework defaults.
