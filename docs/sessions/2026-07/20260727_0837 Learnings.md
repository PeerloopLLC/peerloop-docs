# Conv Learnings - 2026-07-27

## 1. A 200 that renders an empty shell is indistinguishable from an unwired component
**Topics:** verification, testing, seed-data

**Context:** Six icon call sites were reported "unreachable" and shipped with a `NOT VERIFIED` caveat in a decision record. The next turn reached all six.

**Learning:** The routes had always worked. The probe used the handle `brian`, who is neither a teacher nor a creator, so the SSR loaders returned `null`, the pages still returned **200**, and an empty profile shell rendered. "Component didn't render" was read as "route is broken" when it meant "no seed row satisfies this loader's predicate." Before concluding a surface is unreachable, read the loader's `WHERE` clause and check that some seed row satisfies it — here `fetchTeacherProfileData` requires `isTeacherSubquery(users.id)`, and there is no `teachers` table at all (teachers are derived from `teacher_certifications`).

**Pattern:**
```bash
npx wrangler d1 execute peerloop-db --local --json --command \
  "SELECT DISTINCT u.handle FROM users u JOIN teacher_certifications tc ON tc.user_id=u.id"
```
One query answers "who actually satisfies this predicate".

## 2. A token's documented anchor describes the token, not the container it lands in
**Topics:** design-tokens, css, verification

**Context:** Conv 420 migrated `PromoteButton`'s three svgs off a literal 16px to `size-icon-inline-md`, recording it as "the genuine inline case at a **14px** label".

**Learning:** The label is **12px**. `1.15em × 12px` = **13.8px**, so those icons silently shrank 14% and shipped that way for a full conversation — through five green gates and a "no regression" scanner run — because the site was never rendered. A documented ratio ("1.15em, anchored on 14px body text") is a property of the token; what it actually produces depends entirely on the container it inherits from. Measure the call site.

**Pattern:** The counterfactual measurement is cheap and decisive — re-apply the old value to the live element and compare: `el.style.width='1.15em'; el.getBoundingClientRect().width` vs the current rendered width.

## 3. `em` on an SVG inherits from its container, not from the sibling label
**Topics:** css, design-tokens

**Context:** The em inline-icon family existed so icons would "track the text they actually sit next to".

**Learning:** `em` resolves against the element's own computed font-size, which it inherits from its **parent**. A sibling `<span>` carrying its own `text-body-small` has no effect on it. So `<button class="text-body-default"><svg class="1.15em"/><span class="text-body-small">Label</span></button>` sizes the icon off the button's 14px, not the label's 12px. The mechanism only delivers its promise when container and label already share a size — precisely the case where `rem` would have been fine. This is the structural reason the family never fired.

## 4. One string regex over a whole file is desynchronised by a single apostrophe
**Topics:** codemod, tooling

**Context:** The mechanical sweep's first pass silently skipped 80 convertible sites, spread across whole files.

**Learning:** A quote-pairing scan (``/(["'`])((?:\\.|(?!\1)[^\\])*)\1/gs``) over an entire source file pairs quotes greedily from wherever it starts. One apostrophe in JSX prose (`don't`) mis-pairs every quote after it, so the rest of that file is silently mis-parsed. The fix is scope, not a better regex: run the string scan **locally inside each icon tag**, where a mis-pair cannot propagate beyond one tag. Also require **both ends** of a matched string to sit inside the same icon region — checking only the start lets a mis-parsed literal reach out of the region and rewrite classes it should never touch.

**Pattern:** The cheapest proof a codemod converted nothing it shouldn't: a counter it must not move. Here `dimension-bare-numeric` measured **532 before and after**, which rules out the entire wrong-conversion failure mode in one number.

## 5. Two measurement passes must be paired by identity, never by array index
**Topics:** tooling, testing

**Context:** The `tokened-did-not-scale` rule added this conv fired a false positive on `/admin`.

**Learning:** `collect()` skips zero-size elements, so anything changing visibility between the 16px and 24px passes shifts the array. The collision is exact and easy to miss: **at a 24px root a `size-icon-16` measures 24px**, identical to a `size-icon-24` from the 16px pass — so a one-element shift reads as "did not scale". Stamp each element with an id **before** the visibility filter and look up by that id. Whenever two passes over the same DOM can differ in membership, index pairing is a latent false-positive generator.

## 6. Look for the fingerprint that no author would have written
**Topics:** debugging, tailwind

**Context:** Establishing whether `layout/Header.tsx` was genuinely broken or deliberately compact.

**Learning:** Its responsive padding was `px-4 sm:px-6 lg:px-8`, which under the Conv-174 override resolves to **4px → 24px → 8px** — padding that increases then *decreases* across breakpoints, because 6 is not in the overridden set but 4 and 8 are. No author writes that. Where a global override lands on pre-override code, look for internally inconsistent sequences rather than judging any single value; a lone `px-4` is ambiguous, but a non-monotonic responsive ramp is proof.

## 7. A rule that never fires is a pending decision, not a rule
**Topics:** design-system, process

**Context:** The em inline-icon ladder had been the block's open question since Conv 419.

**Learning:** Three separate times the beside-text case arose, and all three were resolved by classifying *around* the ladder rather than using it — AdminNavbar nav rows became "standalone", the 12px glyph group became "repairs", and the 187-site tranche used rem throughout. Each dodge looked locally reasonable and each deferred the same decision. When a mechanism has been routed around every time it was applicable, that is evidence about the mechanism, not about the cases. Counting the dodges is what made the call obvious.
